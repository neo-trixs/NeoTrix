## Defects Found in NeoTrix Design

### D-331-01: No Neuro-Symbolic Digital Twin with Counterfactual Reasoning
**Source**: #2, #4, #6
**Gap**: 2026 research demonstrates that the next inflection point in digital twins is cognitive integration of structured engineering knowledge (MKP, TRIZ) with generative AI within DT frameworks (#2). The neuro-symbolic approach combining temporal transformers + physics-informed constraints + counterfactual reasoning achieves 51.7% failure reduction with 23.1ms latency (#4). NeoTrix's PerceptionBridge connects L2 perception to L5 consciousness but has no digital twin substrate — no real-time virtual replica of physical assets, no counterfactual state generation for "what-if" analysis, no physics-informed neural constraints. The UNS framework with OPC-UA vendor-neutral data integration (#6) achieves 42.25% downtime reduction by unifying sensor, imaging, and 3D scanning data.
**Impact**: NeoTrix cannot model physical systems in real-time, cannot simulate failure cascades, cannot generate counterfactual maintenance scenarios. NT-PHYSICAL has sensors/motors/safety but no virtual replica for predictive reasoning.
**Suggestion**: Implement `nt_physical::digital_twin` with three components: (1) Real-time state synchronizer (sensor→virtual replica), (2) Counterfactual generator (CVAE-based "what-if" state transitions), (3) Physics-informed loss layer embedding domain constraints into neural predictions. Wire to PerceptionBridge for attention-gated DT state broadcasting.

### D-331-02: No Process-Level Digital Twin (Line-Wide Cascade Simulation)
**Source**: #5, #7
**Gap**: Asset-level twins model single machines. 2026 process twins model entire production lines — simulating how a change to one machine cascades through the whole process (#7). This enables failure injection, PM frequency optimization via 90-day operational simulation, and spare-parts prediction based on simulated failure scenarios. NeoTrix's `HeartbeatAggregator` collects per-module health signals but cannot simulate cross-module failure propagation at the process level.
**Impact**: No capability to predict cascading failures across subsystems; no ability to simulate policy changes before committing; blind to second-order effects of maintenance decisions.
**Suggestion**: Extend `HeartbeatAggregator` with `ProcessTwin` layer that models inter-module dependency graph. Add `simulate_failure_cascade(failed_module, duration)` method. Add `optimize_pm_frequency(simulation_horizon_days)` returning cost-optimal maintenance schedule.

### D-331-03: No Open-Set / Zero-Shot Visual Anomaly Detection
**Source**: #10, #11, #12, #16
**Gap**: NeoTrix's `QualityControlPipeline` (alias `QualityGate`) implements AI→human→platform three-stage review but assumes known defect categories (closed-set). 2026 research shows the critical shift is toward open-set detection: UniSpector achieves retraining-free inspection for novel defects via visual prompting (#11), InspectorGPT uses comparative reasoning against defect-free references (#10), and ADSeeker leverages knowledge-grounded RAG for zero-shot anomaly detection (#12). Foundation models + MLLMs are positioned as complementary tools for adaptation, not replacement of specialist models (#16).
**Impact**: NeoTrix cannot detect novel/unknown defect types without retraining; each new defect class requires labeled data collection + model retraining cycle.
**Suggestion**: Add `nt_meta::open_set_detector` module implementing: (1) Visual prompt encoder for reference-comparison paradigm, (2) Knowledge RAG linking detected anomalies to reasoning chains, (3) Confidence-aware routing (low-confidence → human review, per RobustDefect-LLM pattern). Wire to QualityControlPipeline as zero-shot first pass.

### D-331-04: No Defect Severity Grading (Ordinal Morphology-Aware)
**Source**: #14
**Gap**: NeoTrix's quality control classifies pass/fail but lacks fine-grained severity grading. MAOL demonstrates that defect severity is ordinal (not nominal) with morphology-dependent boundaries — a scratch's severity depends on depth, length, and location relative to critical surfaces (#14). The prediction-aware training via localization perturbation makes the system robust to imperfect detected instances in two-stage pipelines.
**Impact**: Binary pass/fail creates unnecessary scrap (slightly defective parts that are still functional) or safety risks (parts that pass binary check but have critical severity).
**Suggestion**: Add `SeverityGrading` enum with ordinal levels (S0-S4) and `MorphologyFeatureExtractor` computing depth/length/area/location metrics. Implement class-conditional adaptive thresholds per defect type. Wire as post-detection stage in QualityControlPipeline.

### D-331-05: No Prescriptive Maintenance (Beyond Predictive)
**Source**: #3, #6
**Gap**: 2026 prescriptive systems go beyond forecasting failures — they recommend specific interventions (reduce load by 15%, replace specific seal) and agentic AI executes these autonomously (scheduling work orders, ordering parts, adjusting parameters) (#3). NeoTrix's NT-REPAIR handles software self-healing but has no prescriptive maintenance engine for physical assets. The UNS framework achieves transition from predictive to prescriptive by recommending and eventually executing remedial actions independently (#6).
**Impact**: NeoTrix can predict but not prescribe; human must interpret predictions and manually plan interventions. No autonomous maintenance execution loop.
**Suggestion**: Add `nt_repair::prescriptive_engine` with: (1) `recommend_intervention(failure_prediction) → ActionPlan`, (2) `execute_action_plan(plan) → WorkOrder` with parts reservation, (3) Confidence thresholds gating autonomous execution vs human approval. Wire to NT-ACT for autonomous work order generation.

### D-331-06: No Hybrid AI-OR Supply Chain Optimization
**Source**: #17, #23, #24
**Gap**: NeoTrix has no supply chain optimization module. 2026 research shows hybrid AI-OR architectures outperform isolated methods (#17), with SCOPE demonstrating that learning operational couplings across departments (assortment+source+cycle+routing) beats optimizing each separately (#23). Agentic AI frameworks with graph-constrained intervention path search achieve 79-83% end-to-end success vs 72-76% for direct LLM reformulation (#24).
**Impact**: No capability for end-to-end supply chain planning; no cross-department coordination; no operational coupling learning.
**Suggestion**: Implement `nt_act::supply_chain_orchestrator` with: (1) Typed entity tokens for products/facilities/routes, (2) Shared operational representation, (3) Sequential decision interfaces (assortment→source→replenishment→routing), (4) System-level utility function. Start with replenishment planning as first use case.

### D-331-07: No Mamba-Based Efficient Temporal Forecasting
**Source**: #20, #22
**Gap**: NeoTrix's temporal processing uses standard LSTM/Transformer architectures. Mamba state space models achieve >90% accuracy with 60% FLOP reduction vs Transformers (#20), enabling real-time deployment on edge devices. GRAPHINE's virtual node diffusion achieves 38.71% MSE reduction for spatiotemporal forecasting (#22). NeoTrix has no SSM backbone for efficient long-sequence temporal modeling.
**Impact**: Higher computational cost for temporal processing; inability to run complex forecasting models on constrained edge hardware.
**Suggestion**: Add `nt_core::mamba_ssm` backbone with linear-time scaling. Implement `SpatiotemporalGraphAttention` for cross-module dependency modeling. Use as drop-in replacement for LSTM in NT-MIND's temporal reasoning and NT-WORLD's event stream processing.

### D-331-08: No Continuous IBP / Autonomous Root Cause Analysis
**Source**: #21, #24
**Gap**: RELEX reports 67% confidence in AI but only 10% trust autonomous decisions (#21). The winning pattern is continuous IBP (replacing monthly cycles with near-real-time reconciliation) and autonomous root cause analysis (agents reconstructing causal chains in days→minutes). SCOPE demonstrates end-to-end coordination across traditionally siloed departments (#23). NeoTrix's ConsciousnessTree runs 6-stage feedback loops but has no continuous planning cycle or autonomous root cause tracing.
**Impact**: No ability to continuously reconcile cross-domain constraints; no autonomous diagnostic chain for system-level anomalies.
**Suggestion**: Add `nt_meta::continuous_ibp` with: (1) Near-real-time constraint reconciliation across domains, (2) Agent-based root cause tracing with evidence chain, (3) Planner-in-the-loop override for high-stakes decisions. Wire to ConsciousnessTree's Fruits→Core stage.

### D-331-09: No Edge-Cloud Collaborative Processing for Industrial Deployment
**Source**: #5, #8, #9
**Gap**: 2026 manufacturing DTs require four-layer architecture: physical→communication→platform→application (#5), with cloud-edge collaborative processing for low-latency decision-making (#8). Visual inspection requires edge deployment for real-time inline inspection (#9). NeoTrix's deployment model is monolithic (single process) with no edge-cloud continuum, no industrial protocol support (OPC-UA, MQTT), and no heterogeneous compute orchestration.
**Impact**: Cannot deploy to industrial environments; cannot run inference at the edge for latency-critical inspection; no protocol bridge to SCADA/PLC systems.
**Suggestion**: Add `nt_physical::edge_cloud_continuum` with: (1) OPC-UA adapter for industrial sensor integration, (2) Model partitioning (edge inference + cloud training), (3) Latency-bounded task scheduling. Add `IndustrialProtocol` trait to L3 embodiment layer.

### D-331-10: No Confidence-Aware Human-AI Collaboration Pattern
**Source**: #15, #16, #21
**Gap**: RobustDefect-LLM demonstrates confidence-aware routing: predictions with confidence <0.90 or top-2 margin <0.10 route to human review, achieving 100% selective accuracy (#15). RELEX reports 54% prefer human-in-the-loop (#21). NeoTrix's GWT broadcasts salient information but has no confidence-gated human escalation mechanism. The Disclosure Ladder (AnchorPromote) in NT-MIND handles tool budget promotion but not decision confidence routing.
**Impact**: All decisions treated equally regardless of confidence; no graceful degradation to human oversight for uncertain decisions.
**Suggestion**: Add `ConfidenceRouter` to GWT with: (1) Per-decision confidence scoring, (2) Threshold-based routing (auto-execute / recommend / escalate), (3) Feedback loop from human decisions to model calibration. Wire to QualityControlPipeline and NT-ACT action execution.
