# 选题方向文档 — 方向三：软件研发全流程协同

**项目名称**：NeoTrix 研发闭环
**参赛方向**：方向三（软件研发全流程协同）
**赛题**：复杂任务多 Agent 自主协同（AgentTeams 必选协同基点 + 阿里云官方用云 Skills 必选）
**团队**：≤3 人（可个人参赛），初赛提交后成员不可变更；复赛全员实名核验
**技术栈**：Rust（`#![forbid(unsafe_code)]` 零 unsafe）· SQLite KB · E8 确定性推理 · AgentTeams（Manager-Workers）· Higress · MCP

## 一、选题定位

**核心命题**：把「多源缺陷聚合 → 代码根因定位 → 修复生成与执行 → 测试验证与发布确认 → 复盘与知识沉淀」串成由 5 类不同职能 Agent 完成的端到端研发闭环，且每次复盘自动沉淀为可复用 Skill，系统越用越强。

**场景契合度**：NeoTrix 本身就是 AI 原生研发工具（23.6 万行、4240 测试），本项目即其自研闭环的对外方案化，天然覆盖方向三全部参考场景：

| 方向三参考场景 | NeoTrix 落点 |
|---|---|
| 多源缺陷/需求聚合去重 | NT-WORLD 采集 + KB FTS5/去重 |
| 代码缺陷自动定位与影响面分析 | NT-MIND E8 推理 + NT-REPAIR 依赖图 |
| 修复方案生成与自动化编码执行 | NT-ACT dev-implementer（TDD）|
| 测试验证与灰度发布确认 | SelfTest T1-T3 + rev-officer 门禁 |
| 上线复盘与研发知识库沉淀 | experience-tree + KB 经验 hub |

## 二、Agent 系统设计（≥3 个不同职能 Agent）

### 2.0 AgentTeams 协同架构（Manager-Workers）

本方案以 AgentTeams 为**必选协同设计基点**。AgentTeams 采用 Manager-Workers 架构：Manager 统一调度多个 Worker，人类经 Matrix 房间全程可见可干预。本方案映射如下：

| AgentTeams 资源 | 本方案角色 |
|---|---|
| **Manager** | 主控协调者：任务拆解、Worker 选择/创建、进度追踪、结果汇总 |
| **Worker A1-A5** | 5 个职能 Agent：采集者/诊断者/实施者/审查者/沉淀者 |
| **Team（可选，复赛）** | A1-A5 打包为一个 Team，Team Leader 维护团队上下文，Manager 仅与 Leader 交互 |
| **Human** | 人类（≤3 人团队）经 Matrix 房间全程观察与干预 |

关键技术机制（AgentTeams 提供，方案直接使用）：
- **Matrix (Tuwunel)**：Agent 与人类所有通信在房间内可见、可回放、可干预
- **MinIO 共享对象存储**：Worker 无状态，配置/任务上下文/产物存对象存储，Worker 可随时替换
- **Higress 网关**：LLM 与 MCP 流量统一入口，Worker 只持消费者令牌，真实凭证（LLM key/GitHub PAT）由网关托管
- **`agt` CLI / REST API**：Worker/Manager/Team/Human 四类 CRD 声明式管理

### 2.1 Agent Identity 清单（附录 A 摘要）

| Agent | 域 | 职能 | 身份定义 | 能力边界 | 协同关系 |
|---|---|---|---|---|---|
| **M0 Manager** | AgentTeams | 主控协调 | 拆解任务、委派 Worker、追踪进度、汇总上报 | 不亲自实施；不自主批准高风险动作 | 调度 A1-A5 |
| **A1 采集者** Collector | NT-WORLD | 缺陷/需求聚合、去重、分级 | 只做摄取与规范化，不做决策 | 不修改代码；只产出结构化证据集 | 输入源 → A2 |
| **A2 诊断者** Diagnostician | NT-MIND + NT-REPAIR | 代码根因定位、影响面分析 | E8 确定性推理，产出带置信度与证据链的根因报告 | 不直接改代码；证据不足不编造 | A1 → 根因给 A3 |
| **A3 实施者** Implementer | NT-ACT | 修复方案生成 + TDD 执行 | 红-绿-重构实施修复，沙箱执行测试 | 只能改授权文件；高风险需审批 | 接 A2 → 产物给 A4 |
| **A4 审查者** Auditor | NT-SHIELD | 独立验证测试、合规审计 | 独立于 A3 验证，产出审计报告 | 只读；一票否决权 | 门禁角色 |
| **A5 沉淀者** Distiller | NT-MEMORY | 复盘蒸馏、Skill 结晶、KB 落盘 | 五阶段吸收协议落盘 | 不参与当次修复决策 | 收全链证据 → 回灌 |

### 2.2 任务拆解（TaskDecomposerDispatcher）

主控 Agent（Orchestrator 型）将研发任务拆为 SubTask 队列，按 `SubTaskClass`（诊断/实施/验证/复盘）分级调度：

```
输入（缺陷 Ticket/告警）
  → 拆解：collect(证据) → diagnose(根因) → implement(修复) → audit(验证) → distill(沉淀)
  → 每步产出结构化中间结论写入 KB nodes/edges（上下文传递载体）
```

E8Plan 六阶段计划生成，步骤状态机 `StepStatus`（Pending→Running→Done/Failed）驱动；分级调度打标 + 确定性内核快路径。

### 2.3 上下文传递

- **任务级**：`CoreEvent` 枚举（`TaskSubmitted` / `AgentTeam` / `AgentFeedback` / `ExternalReward` / `BudgetExceeded`）经双层 EventBus（L1 核心层 + L2 能力层）广播。
- **全局级**：GWT `broadcast()` 写入有界 `active_broadcast` 槽位，`resonance_winner()` 谐振选优决定哪个 Specialist 接收注意；广播历史以 SHA-256 审计链留存。
- **中间结论**：Agent 间传递的根因报告、补丁、测试结果全部结构化为 KB nodes/edges，实现「上下文可追溯、不依赖单次会话内存」。

### 2.4 协同执行与状态追踪

- `OrchestratorPhase` 状态机：Backlog → Planning → Running → Review → Done/Cancelled，每阶段映射 Specialist（Planning→Planner/GoalPrioritizer，Running→CodeAnalyzer/Implementer，Review→ReflectionEngine/MetaCognitionAnalyst）。
- 每个 Agent 以 `SubAgentDef` 定义（E8 模式、`PermissionMatrix` 工具白名单、e8_mode）。
- 失败处理：A4 审查不通过 → 携带审查意见打回 A3 重试（重试次数封顶后升级人工）。

### 2.5 审批与回滚

- 高风险动作（改动生产配置、大范围重构、删除数据）→ `approval.rs` 人工审批门禁，未经批准不执行。
- 修复回滚：A3 变更入版本管理，失败可回滚，执行证据（补丁+测试输出+审查报告）全量保留。
- 审计：`evidence` 强制溯源（file:line / url），gitleaks 密钥扫描，无证据不放行。

### 2.6 结果验证（SelfTest T1-T3 三层接线）

- **T1 Existence**：修复模块 `impl SelfTest` 存在
- **T2 Registration**：注册进 run.rs + pipeline.rs 自检注册表
- **T3 Production Wiring**：`evaluate()`/`check()`/`audit()` 被非测试代码实际调用，输出可影响发布决策（评审维度的「行为生产门禁」）

## 三、AgentTeams 协同基点映射（必选，重点核验）

基于 AgentTeams 官方架构（docs/overview.md + design/architecture.md）实证映射：

| AgentTeams 能力 | 官方机制 | 本方案映射设计 |
|---|---|---|
| **角色编排** | `Worker`/`Manager`/`Team`/`Human` 四类 CRD，Manager 创建/选择 Worker | M0 Manager + A1-A5 Worker；复赛打包 Team（Leader 维护团队上下文） |
| **任务拆解** | Manager 内建 `task-management`/`task-coordination`/`project-management` Skill | 研发任务拆 SubTask 队列（collect→diagnose→implement→audit→distill），Manager 委派各 Worker |
| **上下文传递** | MinIO 共享对象存储（`shared/tasks/` 前缀）+ Matrix 房间时间线 | A1→A2→A3→A4 中间结论写 `shared/tasks/<id>/`；KB 结构化落盘做长程上下文 |
| **协同执行** | Worker 并行执行 + Team Leader 协作单元；Worker 无状态可替换 | 5 Worker 并行/串行闭环，产物存对象存储，任一 Worker 可替换 |
| **状态追踪** | Manager 经 Matrix 追踪进度 + `agt get` 查询 CR 状态 | CoreEvent 事件流 + trace_data + SHA-256 广播链双重追踪 |
| **人工监督** | Matrix 房间 human-in-the-loop，随时可干预/审批 | 高风险动作（改生产/大重构/删数据）经房间人工确认 |
| **安全** | Higress 网关：LLM/MCP 路由 + 消费者令牌，Worker 不持真实凭证 | GitHub PAT/LLM key 全部由 Higress 托管，Worker 仅消费令牌 |

**NeoTrix 差异化定位**：AgentTeams 是协同编排器（管「谁做什么、怎么传递」），NeoTrix 提供**确定性推理内核与自进化知识层**（管「怎么想、怎么沉淀」），两者互补不冲突。对照现有开源 SWE 方案：

| 对比项 | OpenHands / SWE-agent | **本方案（NeoTrix 研发闭环）** |
|---|---|---|
| 推理方式 | 概率式多轮尝试（inference-time scaling + critic 选优） | **E8 确定性 64 态推理**，根因定位可复现 |
| 多 Agent 结构 | 平台内多 agent 委派 | **AgentTeams Manager-Workers 显式编排** + 5 职能 Agent 分工 |
| 结果验证 | 单次测试通过为主 | **SelfTest T1-T3 生产门禁**（4240 测试实测）+ 独立审查者一票否决 |
| 经验沉淀 | 会话记忆，无标准协议 | **experience-tree 五阶段吸收**，复盘自动结晶为 Skill |
| 治理安全 | 沙箱为主 | 审批/回滚/审计链 + 凭证网关隔离 + 零 unsafe |

**迁移成本说明**：AgentTeams 不实现 Agent 逻辑，而是编排 Agent 容器；本方案将 NeoTrix 的 Agent 能力以 **Worker Skill** 形态装载（SKILL.md + scripts），AgentTeams 管理器按需分发到 Worker 工作区 —— 协议适配而非重设计调用链，满足评审要求。

## 四、Skill 工程体系（必选）

|---|---|---|

## 七、可观测设计（推荐）

- **Trace**：Skill 调用 / MCP 工具 / RAG 检索 / LLM 推理全程链路，trace_data 表落盘，广播历史 SHA-256 审计链保证不可篡改。
- **Log**：结构化日志（nt_io_telemetry）+ 会话记录（conversation_records）。
- **Metrics**：修复成功率、平均定位耗时、重试次数、吸收速度（ConsciousnessTree 健康指标、负熵趋势）。
- **应用**：基于观测数据离线评估 Agent 修复质量，驱动 skill 参数自适应（自进化闭环）。

## 八、工程落地与安全审计

- **零 unsafe**：`#![forbid(unsafe_code)]`，Rust 内存安全 + gitleaks 密钥扫描。
- **证据链**：每个闭环动作产出执行证据（日志/Trace/Metrics/补丁/测试输出），evidence 强制溯源。

- **审批/回滚**：approval.rs 人工审批门禁 + 版本回滚 + 审计记录。
- **可运行性**：cargo build/check/test 双验证、Docker 部署、install.sh、CI（.github workflows）。

| 阶段 | 时间 | 交付物 |

### 复赛 Demo 场景（真实可验证）
1. 注入一个真实 GitHub Issue（含复现步骤）→ A1 采集聚合（github-operations Skill 读取）
2. A2 用 E8 推理定位根因（输出证据链，可召回官方用云 Skills 做云资源影响面）
3. A3 按 TDD 生成修复 + 运行测试套件（dev-implementer + 沙箱）
4. A4 独立审查（rev-officer）→ 门禁通过
5. A5 将本次复盘经 experience-tree 落盘，生成新 Skill 或强化既有 Skill
6. 全链路在 AgentTeams Matrix 房间可见可回放，Trace/Metrics 作为运行证据

### 复赛工程化（AgentTeams 接入路径）
1. 本地起步：`install/agentteams-install.sh` 单机部署（embedded controller: Higress+Tuwunel+MinIO+Element Web）
2. 声明式管理：`agt` CLI / YAML 定义 Manager + 5 Worker（OpenClaw 运行时）
3. NeoTrix Agent 能力以 Worker Skill（SKILL.md + scripts）装载，Manager 按需分发
4. 官方用云 Skills 经 skills.aliyun.com 安装到对应 Worker
5. 共享部署：K8s Helm chart（`helm/agentteams`），Higress 网关托管全部凭证
6. 评测：SWE-bench-style issue 集，记录修复成功率/耗时/成本/metrics
