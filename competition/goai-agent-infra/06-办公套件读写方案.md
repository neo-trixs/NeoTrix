# 办公套件读写编辑 — 开源最优解调研

> 目的：为 NeoTrix 补足「基础文档编辑查看能力」（Word/Excel/PPT/PDF 的读取、生成、编辑），用于初赛/复赛材料的自动生成与 Agent 工具链集成。
> 结论先行：**Python 侧统一采用 `python-docx + openpyxl + python-pptx + pypdf` 四件套（读写）+ `markitdown`（读转 Markdown）+ LibreOffice headless（格式保真转 PDF/可视化验证）**；Rust 侧（与 NeoTrix 零 unsafe 同构）备选 `office_oxide`。对外统一封装为 **MCP server**，与 Agent Infra 赛道的 MCP 推荐一致。

---

## 一、遇到的问题（现状复盘）

| # | 问题 | 根因 | 解法 |
|---|---|---|---|
| 1 | 模型无法直接读 PDF（`Cannot read pdf`） | 模型无 PDF 输入能力 | `pypdf` 提取文本 → 分页喂给上下文 |
| 2 | 读取 PPTX 需 unzip + regex 抠 XML | 无高层封装 | `python-pptx` 结构化读取 slide/shape/notes |
| 3 | 读 XLSX/DOCX 需先装库 | 环境缺库 | `openpyxl` / `python-docx` 读写 |
| 4 | 需要「编辑模板并保留原格式」 | 高层库重建模板会丢版式 | Office XML 脚本（unpack→改文本节点→pack）或 LibreOffice 保真 |
| 5 | 需要把文档喂给 LLM 分析 | 文本提取丢结构 | `markitdown` 转 Markdown（保标题/表格/链接） |
| 6 | 需要 PDF/PNG 渲染验证输出 | 无渲染 | LibreOffice headless 转 PDF、`PyMuPDF` 渲染 PNG |

## 二、读取能力（文档 → 文本/Markdown）

### 最优选型

| 任务 | 首选 | 备选 | 说明 |
|---|---|---|---|
| 通用文档→Markdown（喂 LLM） | **`microsoft/markitdown`** | `Pandoc`、Apache Tika | 保标题/列表/表格/链接；LLM 友好；轻量 |
| Word 读取 | `python-docx` | `Mammoth`（→HTML 保真） | 段落/表格/样式/图片 |
| Excel 读取 | `openpyxl` | `pandas`+`pyxlsb`（.xlsb） | 单元格/公式/图表 |
| PPT 读取 | `python-pptx` | `markitdown[pptx]` | slide/shape/notes 全读 |
| PDF 文本 | `pypdf` | `PyMuPDF (fitz)` | pypdf 更轻；fitz 支持图片+渲染 |
| PDF→Markdown | `markitdown` | `pdf2markdown` | 复杂版式建议 Azure Content Understanding（云端） |

### 关键：`markitdown` 的安装方式
```bash
pip install "markitdown[all]"   # 或按需: [pptx] [docx] [xlsx] [pdf]
markitdown input.pptx > out.md  # CLI 一键转
```

## 三、生成与编辑能力

### 3.1 创建（从零建文档）

| 格式 | 首选库 | 覆盖 |
|---|---|---|
| Word | `python-docx` | 段落/表格/图片/样式/页眉页脚 |
| Excel | `xlsxwriter`（新建报告，图表/条件格式） | 新建专用；不能改已有文件 |
| Excel | `openpyxl`（新建+编辑已有） | 覆盖读+写，公式不计算 |
| PPT | `python-pptx` | slide/text/shape/table/image |
| PDF | `reportlab`（复杂排版）/ `WeasyPrint`（HTML→PDF） | 学习曲线陡 |

### 3.2 编辑已有文档（保留原格式 — 关键场景）

**场景：初赛方案 PPT 模板（官方 19 页模板）填充**
- `python-pptx` 可改 slide 内文本/图表，但对**母版/版式/占位符保真有限**。
- 保真方案：**Office XML 脚本**（unzip→改 `<a:t>` 文本节点→zip 重打包），只动文本不动样式，复用 `~/Downloads/AI大赛/初赛作品模版.pptx`。
- 或 LibreOffice headless 复制模板再填充。

**场景：xlsx 报表复用**
- `openpyxl.load_workbook` 只改目标单元格，保留公式/样式/图表。

### 3.3 公式重算 / 格式保真转换
- **公式重算**：openpyxl 不算公式 → 需 Excel COM（Windows）或 **LibreOffice headless**（跨平台）。
- **转 PDF/PNG**：LibreOffice headless（`soffice --headless --convert-to pdf`），用于交付 PDF + 视觉 QA。

## 五、MCP 集成（Agent Infra 赛道推荐路径）

对外封装为 MCP server，Worker 经 Higress 网关调用（凭证网关托管，符合 AgentTeams 安全模型）：

| 候选 | 工具数 | 亮点 | 适用 |
|---|---|---|---|
| **gawirable/office-mcp** | 47 | 读改写格式+PDF/HTML/CSV 导出；schema 规范 | 首选（对齐赛道 MCP 推荐） |
| mhackermsft/OfficeMCP | 20+ | 图片提取 base64 视觉分析；Markdown 写入 | 需文档内图片 OCR/分析 |
| rcarmo/python-office-mcp-server | 30+ | 模板填充+审阅（tracked changes）+审计 | 面向正式文档交付 |
| office_oxide FFI | Rust | 零 unsafe，与 NeoTrix 同栈 | 若需纯 Rust 内嵌 |

**工具契约（附录 B 格式）**：
- 工具名：`office_read` / `office_create` / `office_write` / `office_convert`
- 参数 Schema：path、format、content、target_format
- 幂等：写操作带内容哈希，重复调用不叠加
- 审计：每次调用记 trace + 文件哈希；降级：MCP 不可用→本地 python-docx 直连

## 六、推荐落地方案（NeoTrix）

```
┌─ MCP layer ── office-mcp (gawirable)  ── 经 Higress 供 A1/A3 Worker 调用
├─ Python libs ── python-docx / openpyxl / python-pptx / pypdf / markitdown
├─ Rendering ── LibreOffice headless (转 PDF/PNG 视觉 QA) + PyMuPDF (渲染)
├─ Rust (远期/内嵌) ── office_oxide (零 unsafe, 读改写 round-trip)
└─ Skill ── office-skills (SKILL.md 定义输入输出/失败处理/安全边界, 见附录 B)
```

### 落地优先级
1. **P0（复赛前必须）**：python-docx/openpyxl/python-pptx/pypdf + markitdown —— 完成初赛 PPT 模板填充、作品简介生成、评审文档生成。
2. **P1（复赛 Demo）**：gawirable/office-mcp 接入 AgentTeams Worker；Demo 场景含「A3 实施者自动生成修复报告 .docx/.pdf」。
3. **P2（远期）**：office_oxide Rust 内嵌，取消 Python 依赖，与零 unsafe 架构对齐。

## 七、初赛立即行动（今天可用）

```bash
# 环境已具备
pip install python-pptx openpyxl python-docx pypdf "markitdown[all]"

# 用官方模板生成方案 PPT（脚本见 ../scripts/）
python scripts/build_ppt.py --template ~/Downloads/AI大赛/初赛作品模版.pptx --out 初赛方案.pptx

# 作品简介/附录导出校验
markitdown 初赛方案.pptx > 初赛方案.md   # 回读校验结构
soffice --headless --convert-to pdf 初赛方案.pptx  # 视觉 QA
```
