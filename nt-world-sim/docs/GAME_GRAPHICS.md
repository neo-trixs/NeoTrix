## 5. Rendering Techniques — Making 2D Look Professional

### 5.1 Crisp Pixel Art Rendering (Canvas)

**The Core Rule**: Never let the browser smooth your pixel art.

```css
canvas {
  image-rendering: pixelated;
  image-rendering: crisp-edges;     /* Firefox fallback */
  image-rendering: -moz-crisp-edges;
  image-rendering: -webkit-optimize-contrast;
}
```

**Canvas 2D Context**:
```js
ctx.imageSmoothingEnabled = false;
// Must re-set after every canvas resize!
```

**Integer Scaling** — Pixel art looks best at 1x, 2x, 3x, 4x:
```js
const scale = Math.floor(Math.min(
  window.innerWidth / GAME_WIDTH,
  window.innerHeight / GAME_HEIGHT
));
canvas.style.width = GAME_WIDTH * scale + 'px';
canvas.style.height = GAME_HEIGHT * scale + 'px';
```

**Integer Positions** — Sub-pixel positions cause blur:
```js
// Bad:  ctx.drawImage(sprite, 10.5, 20.3)
// Good: ctx.drawImage(sprite, Math.round(10.5), Math.round(20.3))
```

### 5.2 Responsive Canvas Pattern

```js
class ResponsiveCanvas {
  constructor(canvas, options = {}) {
    this.canvas = canvas;
    this.ctx = canvas.getContext('2d');
    this.gameWidth = options.width || 320;
    this.gameHeight = options.height || 180;
    this.pixelArt = options.pixelArt !== false;
    window.addEventListener('resize', () => this.resize());
    this.resize();
  }

  resize() {
    if (this.pixelArt) {
      const scale = Math.max(1, Math.floor(Math.min(
        window.innerWidth / this.gameWidth,
        window.innerHeight / this.gameHeight
      )));
      this.canvas.width = this.gameWidth;
      this.canvas.height = this.gameHeight;
      this.canvas.style.width = this.gameWidth * scale + 'px';
      this.canvas.style.height = this.gameHeight * scale + 'px';
      this.canvas.style.imageRendering = 'pixelated';
      this.ctx.imageSmoothingEnabled = false;
    }
  }
}
```

### 5.3 Phaser Configuration

```js
// For big-pixel look (scaled sprites):
{ render: { smoothPixelArt: true } }

// For crisp 1:1 pixels:
{ render: { pixelArt: true } }

// Round pixel positions:
game.renderer.renderSession.roundPixels = true;
Phaser.Canvas.setImageRenderingCrisp(game.canvas);
```

## 6. Shadows and Lighting — 2D Techniques

### 6.1 Simple Drop Shadows (Canvas API)

```js
ctx.shadowColor = 'rgba(0, 0, 0, 0.5)';
ctx.shadowBlur = 8;
ctx.shadowOffsetX = 4;
ctx.shadowOffsetY = 4;
ctx.fillRect(x, y, width, height);
```

### 6.2 Directional Shadows (Sun Simulation)

Based on sun angle, calculate shadow length and opacity:
```js
const sin = Math.sin(sunAngle * Math.PI / 180);
const cos = Math.cos(sunAngle * Math.PI / 180);
const shadowLength = objectHeight * cos;
const shadowOpacity = 0.4 * sin;

ctx.fillStyle = `rgba(0,0,0,${shadowOpacity})`;
// Draw parallelogram shadow from object base
```

Key principles:
- Shadow length ∝ `cos(sunAngle)` — shortest at noon, longest at sunrise/sunset
- Shadow opacity ∝ `sin(sunAngle)` — faintest at horizon, darkest at noon
- Shadow direction perpendicular to light source

### 6.3 Multi-Light Source Technique (Canvas)

```js
// Create shadow layer (offscreen canvas)
const shadowCanvas = document.createElement('canvas');
const shadowCtx = shadowCanvas.getContext('2d');

// Fill with darkness
shadowCtx.fillStyle = '#000';
shadowCtx.fillRect(0, 0, w, h);

// Cut out light sources using destination-out
shadowCtx.globalCompositeOperation = 'destination-out';
const gradient = shadowCtx.createRadialGradient(x, y, 0, x, y, radius);
gradient.addColorStop(0, 'rgba(255,255,255,1.0)');
gradient.addColorStop(1, 'rgba(255,255,255,0.1)');
shadowCtx.fillStyle = gradient;
shadowCtx.fillRect(0, 0, w, h);

// Overlay shadow layer on game canvas
ctx.drawImage(shadowCanvas, 0, 0);
```

### 6.4 WebGL Normal Map Lighting

For dynamic per-pixel lighting:
1. Create normal maps for sprites (RGB = XYZ surface normals)
2. Pass light position/direction as uniforms to fragment shader
3. Calculate `dot(normal, lightDir)` per pixel for diffuse lighting
4. Use height maps for shadow casting (ray marching toward light)

### 6.5 Color Dodge Atmospheric Lighting

```js
ctx.globalCompositeOperation = 'color-dodge';
ctx.fillStyle = lightColor;
ctx.beginPath();
ctx.arc(lightX, lightY, radius, 0, Math.PI * 2);
ctx.fill();
ctx.globalCompositeOperation = 'source-over';
```

## 7. Smooth Graphics — Anti-Aliasing & Pixel Scaling

### 7.1 Scaling Algorithms

| Algorithm | When to Use | Canvas Method |
|-----------|------------|---------------|
| **Nearest Neighbor** | Pixel art (preserves hard edges) | `imageSmoothingEnabled = false` |
| **Bilinear** | Photos, smooth art | `imageSmoothingEnabled = true`, `imageSmoothingQuality = 'low'` |
| **Bicubic** | High-quality photo scaling | `imageSmoothingQuality = 'high'` |

### 7.2 Anti-Aliasing in Pixel Art

**When to use AA**: Interior details only (gradients on faces, curved surfaces)
**When to NOT use AA**: Outlines, silhouettes, edges — these stay sharp

```css
/* CSS approach for canvas games */
canvas {
  image-rendering: pixelated;          /* Chrome/Safari */
  image-rendering: crisp-edges;        /* Firefox */
  -ms-interpolation-mode: nearest-neighbor; /* IE */
}
```

### 7.3 Pixel-Perfect Rendering Checklist

1. ✅ Canvas internal size = game resolution (e.g., 320x180)
2. ✅ CSS size = integer multiple of internal size
3. ✅ `imageSmoothingEnabled = false` set after every resize
4. ✅ All sprite positions rounded to integers
5. ✅ All sprite dimensions are integer multiples of original
6. ✅ `image-rendering: pixelated` on canvas element
7. ✅ No fractional `ctx.scale()` values

## 8. Art Style Guide — Consistent Visual Design

### 8.1 Resolution Standards

| Style | Sprite Size | Colors | Example Games |
|-------|-------------|--------|---------------|
| **8-bit / Lo-fi** | 8x8 to 16x16 | 4-16 | Shovel Knight, Downwell, Celeste Classic |
| **16-bit / Classic** | 16x16 to 32x32 | 16-32 | Stardew Valley, CrossCode, Katana ZERO |
| **Hi-bit / Modern** | 32x32 to 128x128 | 32-256+ | Hyper Light Drifter, Dead Cells, Eastward |

**Recommendation**: 32x32 is the sweet spot — readable faces, manageable production, classic feel.

### 8.2 Color Palette Rules

1. **Lock a palette early** — Use one shared palette across all assets
2. **3-shade rule**: Base color + Shadow (darker, hue-shifted) + Highlight (lighter, hue-shifted)
3. **Hue shifting**: Don't just darken with black. Red shadows → red-purple. Red highlights → orange-yellow
4. **Palette size**: 16-32 colors for most indie games
5. **Desaturate most colors** — reserve full saturation for highlights, magic, pickups

**Recommended Community Palettes**: PICO-8 (16 colors), Endesga 32, AAP-64

### 8.3 Outline Rules

- **Pick ONE style**: black outline, colored outline, or no outline — never mix
- 1px black outlines are most common and safest
- Colored outlines (darker shade of base color) look softer — used in Stardew Valley
- Outlines should be darker than the darkest part of the sprite
- No opacity on outlines (solid color)

### 8.4 Shading Rules

- **Light direction**: Upper-left is standard — keep consistent across ALL assets
- **Never pillow-shade** (shading all edges equally) — use directional lighting
- **3-tone minimum**: Base → Shadow → Highlight for each material
- Shadows follow geometry, not just "darken everything"

### 8.5 Animation Timing

| Action | Frame Count | Duration |
|--------|-------------|----------|
| Idle | 2-4 frames | 80-120ms per frame |
| Walk | 6-8 frames | 80-100ms per frame |
| Attack | 4-6 frames | 60-80ms per frame (snappy) |
| Jump | 3-4 frames | Variable (slow up, fast down) |

- Variable frame duration: slow anticipation → fast action → slow recovery
- Squash and stretch applies even at 16x16 (1px compression/stretch)
- Consistent timing across all entities

### 8.6 Style Bible Template

Write 12 lines before drawing your second asset:

```
Project: [Name]
Resolution: [32x32 characters, 16x16 tiles]
Palette: [PICO-8 / custom / Endesga 32]
Outlines: [1px black / colored / none]
Shading: [2-tone cel / full gradient / dithered]
Light source: [Upper-left, 45°]
Animation: [80ms base, walk 6f, attack 4f]
Proportions: [2.5 heads tall / chibi / realistic]
Outline rule: [Always 1px black, no exceptions]
Tile size: [16x16 grid, seamless]
Background contrast: [Never stronger than player sprite]
```
