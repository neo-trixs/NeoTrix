### 2.1 `.nb-main` 的根因：两份交接各修了一半 ⭐

| 来源 | 主张 |
|---|---|
| `f38acb0f` §3 | 缺 `flex: 1 1 auto`（实测 213px → 792px）；并写「上次加了 `display:flex`，把 `flex:1 1 auto` 删掉了」 |
| 本侧 | 缺 `display: flex`（实测子元素 `flex:1 1 0%` 在 block 父级下无处生效，容器撑到 3168px） |

**少任一条都会坏，且构建/类型/渲染全绿** —— 这正是两份交接各修一半的根源。

### 2.3 ⭐ Git 用法：两份交接**直接冲突**，各对一半

| 来源 | 主张 |
|---|---|
| `f38acb0f` §7.5 | `git commit -- <paths>` **只暂存已跟踪文件** ⇒ 新文件进不了库（而 `lib.rs` 已 `pub mod menu;` ⇒ **提交态编译不过**）⇒ **必须 `git add -A`** |
| 本侧 | 共享树下 `git add -A <目录>` **卷走另一窗口在途文件**（实测卷走他窗自研桌宠 4 文件）⇒ **永不用 `-A`** |

**裁决：两者作用域不同，都对。** 实测支撑：
- 未跟踪新文件：`git commit --only <新文件>` ⇒ `pathspec ... did not match any file(s) known to git`（本侧撞过）
- `-A` 作用于共享目录 ⇒ 会吸进他窗新文件（本侧撞过，且已 `reset --soft` 回退重做）

⇒ **统一规则**：
```sh
git add <显式列出的路径>            # 只列自己的，逐个写，不用 -A
git commit --only <同一批路径>      # 新文件此时已被跟踪，--only 生效
```
**既满足「新文件必须入库」，又不会吸走别人的文件。**
