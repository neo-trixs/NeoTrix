# arch_fitness_dead_code 豁免基线（裁定 1A，2026-10-07）
#
# 语义：某条 failure 含任一**子串**即跳过。空文件 = 无豁免（最严）。
# ⚠️ 纪律：豁免**必须逐条、带理由**。本文件里每一条都要能回答：
#    「这个模块为什么需要压掉编译器信号？」
#
# ───────────────────────────────────────────────────────────────────
# 【规则】本文件登记的全部是**模块级** `#![allow(dead_code)]`
#（形如 `neotrix-core/src/.../foo.rs` 内部），**不是** crate 级的
# `lib.rs:23`。每条都有自己的模块文档，不是无脑复制的样板。
#
# 【为什么整体豁免而非逐个删 allow】
# 裁定 1A 已定：`lib.rs:23` 的 crate 级 allow 是**有意的** R-P1 约定，
# 保留它、由本门补位。同一约定在模块级的一致应用（"这个模块的类型体系
# 面向未来接线，先不因未接线产生编译噪声"）属同类工程判断。
# ⇒ 本门的作用从"禁止一切 allow"变为**"禁止没有登记的 allow"**：
#    新增一个 `#![allow(dead_code)]` 而不登记 ⇒ CI 立刻红。
#    这正是 LESSONS L8 判据②「结果被消费为门」的实际兑现。
#
# 【不豁免什么】
# ⛔ 零消费者模块（跨域错位、已废弃实现）**不**靠 allow 豁免 ——
#    那类应删除或归档（见 roadmap T1-*），不是登记了事。
#    本文件里若出现这类条目，即为误登记，应重新裁决。

# ── crate 级（本裁定 1A 的核心豁免）────────────────────────────────
# `lib.rs:23` 的 `#![allow(dead_code)]` 是**有意的** R-P1 约定 —— 保留它。
# 理由链：
#   ① 保留约定，用 `DeadCodeFitness` 补位被压掉的编译器信号（本裁定的做法）；
#   ② 备选方案 B「删 allow、交还编译器」已否决：2483 文件 / 784,660 行
#      从未被编译器审过，删掉会立刻爆出大量 dead_code 噪声；
#   ③ 历史旁证：`recovery.rs:37-39` 特意加模块级 `#![deny(dead_code)]`
#      来对抗它 —— 说明已有人试过"交还编译器"并退回。
# ⚠️ 本条豁免的是**这一处约定**，不是"全仓死代码"。新引入的模块级 allow
#    仍须逐条登记，否则本门立刻红。
neotrix-core/src/lib.rs
