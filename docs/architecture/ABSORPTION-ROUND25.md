# ABSORPTION-ROUND25 — G5 全域存活率 + 抓到 ROUND15「落地未接线」（2026-09-30）

> 触发：被问「每个 URL 都吸收完了吗？全域 code map 都迭代分析了吗？」
> 实测回答是**否**，且缺口集中在一点：**存活率门只覆盖 1/32 份吸收文档**。
> 本轮把 G5 从单文档扩到全域，并因此在**既有轮次**上抓到一个真实缺陷。

## 1. 为什么要做

`nt_absorption_live.py` 的抽取器硬编码了 `### 1.1` / `### 1.3` —— 那是
`ABSORPTION-MAP-TASKS-2026-09-29.md` **专有**的章节标记。
⇒ 32 份吸收文档里 **31 份的落地断言从未被任何机制验证过**。

这同时回答了「吸收完了吗」：**没人能回答**，因为没工具能问。

## 2. 抽取判据（分级，宁缺勿错）

| 级 | 载体 | 覆盖文档 | 抽取方式 |
|---|---|---|---|
| **A** | `\| L-xxx \| 产物 \| 验证 \|` 表格行 | 43 | 第 2 列反引号 token |
| **B** | `## N. Landings` 段正文 | 7 | 该段全部反引号 token |
| **C** | 两者都无 | 13 | **记 unverifiable，不凑数** |

⛔ C 级**故意不参与统计**：凑数会把「源清单」「Deferred」「外部引用」当成落地，
制造假阳性。13 份 C 级里含 `ABSORPTION-GRAPHIFY.md`（632 行）这种大文档 ——
它的内容是真的，只是**没写成可判格式**（属文档债，不是「没吸收」）。

## 3. 结果【实测】

```
文档 A/B/C = 43/7/13
token 存活=36  搬迁=17  死亡=0  导出未接线=5  不可判=4  外部=4
```

### 3.1 ⛔ 「0 死亡」**不等于**健康 —— 判据偏宽，必须说清

工具自己的 docstring 写着「若报全部存活说明判据无效」。
本轮**确实报 0 死亡**，原因是 `find_file` 允许
「任意 basename 在 `git ls-files` 里存在就算存活」——
那 17 条「搬迁」全是文档只写了裸文件名（如 `nt_locate.py`）而文件在别处，
**它们是活的**。
⇒ **本判据偏宽**，`死亡=0` 不可当作吸收健康证明。真信号是下一项。

### 3.2 ✅ 抓到的真实缺陷：ROUND15 的三个组件**全部未接线**

`--graph` 标出 5 条「文本存活但生产不可达」。逐条手验（花括号配平判
`#[cfg(test)]`，**不用行号回看**——回看窗口本会话已证不可靠）：

| token | 手验结论 |
|---|---|
| `nt_net` / `nt_utility` | **不是符号** —— 是 `pub mod` 声明。图判对，文档 token 不精确 |
| `descend` | 是**方法** `pub fn descend(&self,…)`（`nt_flow.rs:63`），我第一轮把它归为「不是符号」是**错的** |
| **`astar`** | `nt_flow.rs:267 pub fn`，生产调用点 **0**，13 处全在 `#[cfg(test)]` |
| **`build_flow`** | `nt_flow.rs:110 pub fn`，生产调用点 **0**，8 处全在 `#[cfg(test)]` |
| **`descend` 方法** | 生产调用点 **0**（唯一「PROD」命中是定义行本身），3 处全在测试 |

而 `ABSORPTION-ROUND15.md:23` 声称落地的是一套**调度策略**：

> 单对单 → `astar`（启发+早停）；多对一 → `build_flow` 一次算完 + `descend` 查表。

⇒ **算法本体落地了、也测了，但那个「选择用哪个」的调度层从未建。**
这就是 R-P79「导出 ≠ 接入」的标准形态，而且是**别人轮次**的债。

⚠️ 仍保留的不确定性：F6 盲区（按值注册）无法完全排除。
但寻路函数不存在合理的注册 API 会接收它，故置信度高。
**即便如此也不建议直接删** —— 判死须读代码 + 删后跑全量测试。
