## P1-1b · Observer-only 子会话投影（设计 + 落地方案）

### 目标
同一 convo 里由**子任务/系统事件**触发写进 messages 的行，必须在 UI/CLI 父视图里**可见、可区分、不可冒充用户**：父聊天默认不显示这些行，显式切换才可见。

### 现调用点锚点（先 grep 现场，再动刀）
1. `crates/neotrix-neobot/src/nt_store/mod.rs`
   - `messages` 表当前列：`id, convo_id, role, text, created_at, platform_msg_id, delivery_status`（line ~470-483）；
   - 读行按位置 `r.get(0..5)`（line ~631 注释，**禁止在中间插列**）。
2. 写路径：
   - `nt_channel_dispatch` 的出站/入站（找 `INSERT INTO messages`）；
   - `nt_agent` run_loop 只写 ledger/steps，**当前 messages 不进 model transcript** ⇒ 子会话投影的载体待定（同步 station 或新建 `system_notes` 视图）。
3. 消费路径：
   - `nt_store_messages` getter/list 先查 `SELECT id,convo_id,role,text,created_at ...`；UI/CLI 消费者待列举。

### 设计（最小可落地）
- **字段**：`messages.origin TEXT NOT NULL DEFAULT 'human'`（ALTER 追加在末尾，幂等，存量行补 'human'）。
- **写约定**：
  - 真用户 echo、管道 stdin 触发的 assistant 回复 ⇒ `origin='human'`（现状等价）；
  - 来自 `tasks` 异步投递、系统事件通知、自动恢复（crash-recovery）的可见消息 ⇒ `origin='agent'`；
  - 新区分不得改变既有 `delivery_status` 语义。
- **读约定**：
  - 父会话默认查询加 `WHERE origin='human'`（保持现有语义不变）；
  - 显式 observer 模式（新 flag `--with-agent-events`）放开 `origin='agent'` 行。
- **反模式**：不往 `role` 里硬塞 `'system'`——`role` 已带既有枚举语义（user/assistant/tool），新开一轴交给 `origin`。

### 切分（建议 2 个 PR）
- **PR-a（字段+写+读默认隐藏）**
  1. `mod.rs` migration：`ALTER TABLE messages ADD COLUMN origin TEXT NOT NULL DEFAULT 'human'` + 幂等 `.ok()` 吞 duplicate-column；
  2. `nt_store_messages` 插入路径签名加 `origin` 参数（默认值给 'human' 的兼容导出器/路径显式补值）；
  3. list 函数默认 `WHERE origin='human'`，另设 `list_messages_visible(convo_id, with_agent)`；
  4. grep 全部 INSERT 调用点补参数（禁用 fall-through，写一个 all-paths 单测）。
- **PR-b（系统/子任务写 origin='agent'）**
  1. `nt_agent`/`nt_channel_dispatch` 对异步 task 投递结果落 `origin='agent'`；
  2. crash-recovery 触发的可见 message 同规则。

### 验收
- 单测 4 条：迁移幂等 / agent 行存量无 / 默认查询不混 / `--with-agent-events` 能读到。
- `cargo test -p neotrix-neobot --lib nt_store` 全绿；`nt_lock_audit` 0。
- `nt_smoke.sh` 探针如触发 messages 读，确认默认行为与旧一致。

决策点（开工时确认）：①「子会话」在 neobot 的实际对象 = 同 convo 下由非人事件写入的可见行，**不是** Captain 的 agent 树（我们没树）⇒ 本方案按「可见出处轴」落地；② UI/CLI 顶层「事件」筛选 UI 元素是路线图 P1 面，不在本 PR。

## P1-4 · clippy 分级收口（小切）

### 目标
让 `cargo clippy --lib -p neotrix` 从「结构性红 ≈ 43161 error」变成「可用作门的红」，先清 pedantic 一半。

### 现状基线（2026-10-08 实测）
```
$ cargo clippy --no-deps -p neotrix --lib
error: could not compile `neotrix` (lib) due to 43161 previous errors
样例：must_use ×9102 | doc_markdown ×5969 | uninlined_format_args ×4574 | indexing_slicing ×3826 | missing_errors_doc ×2056
结构成因：neotrix-core/src/lib.rs:21 `#![warn(clippy::all, clippy::pedantic)]` +
          neotrix-core/src/lib.rs:22 `#![cfg_attr(not(test), deny(warnings))]` ⇒ 任何 pedantic WARN 升成 ERROR
```

### 小切方案（先动属性，不动函数体）
1. **测量切分**（给本次改动争出证据）：
   - `cargo clippy --no-deps -p neotrix --lib 2>&1 | tee /tmp/clippy_before.log`
   - 按 lint 名聚合：`grep ^error /tmp/clippy_before.log | sort | uniq -c | sort -rn | head`
   - 给每个 lint 记属 `all` 还是 `pedantic`（对照 rust-clippy 索引），切分 pedantic 子集估计数。
2. **改 `lib.rs:21`**：`#![warn(clippy::all, clippy::pedantic)]` → `#![warn(clippy::all)]`。
   - 即 crate 级不再默认开 pedantic。
3. **白名单模块手动开回 pedantic**（「细分为该模块放行」）：对想保 pedantic 纪律的模块（新增 invasive 改动的、或现在正洁的），在其 `mod` 文件对应 crate root 加
   - `#![warn(clippy::pedantic)]`——注意这会对该模块里 `deny(warnings)` 同样生效（同结构）。
   - 提议白名单起步（待定量后再定）：`entry/*` 已有 monotone（status/discover）与 `nt_lane` 新代码。
4. **比对**：`cargo clippy --no-deps -p neotrix --lib 2>&1 | tee /tmp/clippy_after.log`；
   - 预期「before 43161 → after ≈ all-only 子集」显著下降；剩余的 all-only error 记录为下一步清扫表。
5. **不许做**：
   - ❌ 不要同时放宽 `deny(warnings)`（那不是「细分」，是「撤哨」）；
   - ❌ 不要顺手改函数体静默错误 —— 结构属性切分只动 attr 行。

### 验收
- `cargo clippy --lib -p neotrix` 的 error 统计**显著低于**基线 43161（记录在本文 + OPEN-DEFECTS N4）。
- `cargo test -p neotrix --lib <白名单模块>` 不变绿；`nt_lock_audit` 0。
- OPEN-DEFECTS N4 行更新：新时间点 + 新计数 + 剩件（all-only 清扫计划）。

### 剩件（后续 PR）
- all-only error 表（mandelbro 式割接：能 `cargo fix --allow-dirty` 自动处理的先做，剩下人肉 shim）。
- pedantic 白名单慢加（新建模块默认 pedantic；旧模块先不回车石）。
