# 验证是可执行的，不只是自觉 —— 2026-09-28 一个会话的 9 次翻车

> 本档记录**方法论**（可迁移的教训），不记录具体修了什么。
> 规约条目见 `RUST-STANDARDS.md` §17.7 的 R-DISK-1~8 / R-SCAN-4。
> 与同目录另三档的区别：那三档讲单次事故，本档讲**一条共同根因**。

## 元教训

**一个会话里出现 9 次「结论与实测矛盾」，全部因为「验证」只存在于文字里。**

AGENTS.md 通篇要求「关键结论标注来源 URL 和文件路径」「门记录必须带核实
时间戳」「R-P16 编辑后重读」——这些都**正确**，但它们是**散文要求**，
没有任何机制能检查 agent 是否照做。9 次翻车里，至少 7 次是因为「我以为
我验证了」。

下面 9 条按「症状 → 根因 → 机械化」排列，每条都已落成代码门。

## 1. 测逻辑 ≠ 测可达性（R-DISK-8）

**症状**：给 `.githooks/pre-push` 追加了一段收工门，并用 mock 验证了它的
三档分支全部正确。但它 **3 天从未执行过** —— 该文件第 24 行原有 `exit 0`，
hook 到那里就终止了。

**根因**：mock 测的是**函数**的逻辑，我测的也是；但我**没测调用链**是否到达它。

**机械化**：`bash -c 'set -euo pipefail; <前置通过路径>; echo REACHED'`，
或 `bash -x hook 2>&1 | grep REACHED`。

**通则**：`bash -n` 只检查 shell 语法，**heredoc 里的 Python 它完全不管**；
抽出 heredoc 体 `ast.parse` 才是真验。

## 2. 路径不存在 ≠ 该面为空

**症状**：`check-api-surface.sh` 打印 `Tauri commands: 0`。桌面端已归档，
但脚本仍带 `src-tauri/src` 路径；`rg` 对不存在路径 **exit 2** 并写 stderr，
`2>/dev/null` 吞掉它，`awk` 仍照常输出 `0`。

**根因**：把「我没扫那个面」与「那个面是空的」混为一谈。读输出的人会得出
「本仓没有 Tauri 命令面」——**一个看起来正常的假数字**。

**机械化**：`nt_scan_surface.py` 扫所有扫描器的扫描面是否存在。
核心判据写进代码注释：`路径不存在 ≠ 该面为空`。
下游脚本面缺失时必须打 `?` + 退出码非 0，**绝不打 0**。

## 3. 只看值会掩盖失败信号

**症状**：修 #2 时写 `[ "$ROUTES" -eq 2 ]` 判失败，而 `ROUTES` 是
`$(count_in ...)` 的结果 —— 函数失败时它是**空串**，对空串做整数比较报
`integer expression expected`，**掩盖了本该显式的失败**。

**机械化**：用**退出码**判失败，不用输出值。

**通则**：值可能是"看起来正常的错"，退出码不会。

## 4. 过滤器同时滤掉噪声和新问题

**症状**：`nt_scan_surface.py` 首版有 `if 根不在 KNOWN_ROOTS: continue`
（为压噪声）。结果注入的 `("definitely-gone-dir","x")` 完全不被报出 ——
**用它防死引用这件事本身有盲区**。

**根因**：过滤器和检测器共用一条判据。

**机械化**：三级分档（现存 / 硬缺失 / 待确认），**宁可多报也不静默丢弃**；
只有硬缺失进退出码。门的可靠性优先于门的干净。

## 5. 守门工具自身噪声大 = 没守

**症状**：同 #4 那个工具，首版 20 个 MISSING 里大半是假警报（注释里的
`foo/bar.rs`、输出文案里的 `Axum/Tauri`、lang/ext 映射值 `yaml`/`json`）。

**根因**：人只会忽略报噪声的门 ⇒ 调低灵敏度换"看起来干净"是错的方向。

**机械化**：逐条登记豁免（`PROSE_PATHS` / `KNOWN_GONE` /
`DETECTION_TARGETS`），并**用注入法自测**：
往目标文件注入已知死引用，验证工具报得出。

## 6. 请示后仍须复核现场（R-SCAN-4）

**症状**：门红在他窗未提交文件，我取证确认归属后向用户请示，
用户选定「顺手删掉那个 unused import」。**动手前复核那一行** —— 内容已变、
mtime 是 42 秒前：那个窗口还活着，且已自己修好。

**根因**：请示与执行之间存在时间窗，那个窗口里世界可能已变。

**机械化**：动手前复核一次现场。已有的「mtime 近期变动 = 他方在写」
纪律管的是决策**之前**；本条管的是决策**已做出、尚未执行**的阶段。

## 7. 手写的冗余期望值 = 手写的不变式 = 迟早写反

**症状**：写 `SkillInvocationPolicy` 四组合的测试，把期望值手写成第三四列，
结果把 `model_invocable` 与 `disable_model_invocation` 的**极性写反** ——
构造 `(mi=false, ui=true)` 却断言 `visible_to_model()==true`。

**机械化**：改用**语义恒等式**由输入推导期望值
（`visible_to_model() == !disable_model`），从结构上消除写反的可能。

**通则**：测试里手写一个能从输入算出来的值 = 手写了一个不变式 = 它会错。

## 8. 外部结论也要实测

**症状**：调研报告的头条是「所有 skill 因文件名不是 `SKILL.md` 而在兼容
agent 里不可发现」。**实测证伪**：67 个 `SKILL.md` 齐备，59 条索引路径
零缺失。照原结论做会白改 100+ 个文件。

**机械化**：`nt_manifest.py add --evidence` 要求带 `file:line`，
`--audit` 校验行号仍有效。**证伪的结论也值得记录** —— 存下来，下个 agent
就不会重踩。

## 9. 治理数据也是数据

**症状**：`layer-map.json` 的 `trees` 记 51 文件/19,371 行，实际 52/21,247。
我先前只把 `_rule`（重名计数）当会过期的数据。

**机械化**：按 **HEAD 口径**（逐文件 `git show HEAD:<path>` 计数，而非工作树
`wc -l` —— 后者会含未入库内容）重测；数字与裁决同等对待。
`nt_find --audit` / `nt_manifest --audit` / `nt_scan_surface` 三门同源。

## 10. 检查的覆盖面本身也会漂

**症状**：`check-skill-gate.sh` 加死链检查时，初版**只在 `index.json` 覆盖的
条目里查**。而 `skills/SKILL.md`（顶层导航，含全部分类的链接表）**不在索引里**
⇒ 注入的死链照样过。注入法自测才抓到。

**根因**：把「已注册的对象」当成了「全部对象」。索引本身是另一份会漂的数据。

**机械化**：覆盖面不足的门是**假门**。自测必须用**注入法** ——
往**已知不在索引里**的位置注入一个已知坏值，看门报不报得出。
`nt_scan_surface` 的盲区 #1（KNOWN_ROOTS 过滤器）和这里的盲区同型：
**过滤器与检测器共用判据时，噪声和新问题一起被吞掉。**

---

## 一条元规则

> **把「我验证了」变成可检查的记录，而不是可信赖的声明。**

本会话 10 次翻车里，**没有一次是因为想得不认真**，全部是因为验证只存在于
叙述中 —— 或验证本身有覆盖面盲区。规则写得再细，只要它是散文，就会有下一次。

而**检查本身**也要用注入法自测覆盖面：一份覆盖面不足的门，比没有门更危险，
因为它让人以为「已经查过了」。

对应的三个门（都已接 pre-commit blocking）：

| 门 | 防的是 | 来自 |
|---|---|---|
| `nt_manifest.py --audit` | 证据的 file:line 已失效 | #1 #3 #8 |
| `nt_scan_surface.py` | 扫描面已消失 ⇒ 假 0 | #2 #4 #5 |
| `nt_find.py --audit` | 索引指向的工具不存在 | #9 |
| `check-skill-gate.sh` 死链 | 文档链接指向不存在的目录 | #2 #10 |
