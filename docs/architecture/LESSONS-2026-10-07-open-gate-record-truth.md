## L1 ⭐⭐⭐ 「吸收永不被开源阻断」≠「记录可以含糊」

用户要的是「门开着」。字面执行会顺手把**记录诚实**一起拆掉 —— 那正是本仓
`check-license.sh` 唯一守着的东西。

⇒ **本轮定的分界（NTS-B10.4）**：

| 可以放松 | 绝不放松 |
|---|---|
| 入参形式（裸 URL 即完整入参） | 记录的许可/来源**必须与事实一致** |
| 是否克隆、是否预批准 | **无 LICENSE ⇒ 只取设计，不取逐字代码** |
| 前置门答不出 → 不否决 | 门脚本的 deny 名单**不得为了变绿而删** |

⭐ **一句可复用的判据**：**门可以宽，门框必须实。**

### 本轮实证：这条界不是空话

`context_fs.rs` 第 1 行写着「基于 OpenViking 模式」，
而 **OpenViking 是 AGPL-3.0**（raw 实测）。
⇒ 我方**取的是模式（虚拟 FS），模式不受版权保护** —— 没抄代码。
但若记录只写「基于 X 模式」而不写「未取代码」，
**下一个读者会推断我方 vendor 了 AGPL**。

⇒ 该做的**不是删代码**（代码本就合规），是**让记录说清「模式来源 + 未取代码」**。

## L2 ⭐⭐⭐ 许可核实：主路径是 `raw`，不是 API

**实测**：GitHub REST API 匿名请求 **403 限流**（`API rate limit exceeded`）。
若就此下「许可未知」，18 仓里 **4 仓**会被误归为「无许可 ⇒ 不可用」。

⇒ 逐仓 × {main,master} × {LICENSE, LICENSE.md, LICENSE.txt, COPYING} 打
`raw.githubusercontent.com` ⇒ **18/18 全部拿到**。

### 三条连带教训
1. **默认分支 ≠ main。** `NevaMind-AI/memU` 的 LICENSE 叫 **`LICENSE.txt`**，
   在 `main/LICENSE` 永远 404。
2. **首行可能是空的。** Apache-2.0 正文首行是缩进 ⇒ `head -1` 得到空白，
   必须 `grep -v '^\s*$' | head` 再读。
3. **`❌ 无 LICENSE` 不等于「同一个结论」。** 它与 AGPL、与非商用**是三种档**，
   但处置**不同**：AGPL 代码层否决、非商用待商用确认、无许可只取设计。

## L7 ⭐ 本机 `rg` 会吞掉标识符

`rg 'trajectory_compressor'` 的输出里，模块名被整体替换成字母 **`n`**：


（`grep`/`sed`/`read` 换一条），两者一致才算数。

## L8 ⭐⭐⭐ **绿色不等于有效** —— 一条"保证"要同时成立三条

场景：为「冗余 + 扁平缺陷 + 跨域错位」做全量评测。
架构门全绿（`check-layer-deps --strict` rc=0、`check-truth-surface` rc=0、
`layer-map` 零漂移、`cargo check` rc=0）⇒ **看起来很干净**。

**结果 3 条 P0 里 2 条是「报告 PASS 但结构上不可能失败」。**

### ⭐ 判据（可直接复用）：一条"保证"须**同时**满足三条

| # | 条 | 反例形态 |
|---|---|---|
| ① | 检测器**能被触发** | 喂真实输入能冒出失败 |
| ② | 结果**被消费为门** | 断言 `.passed`，不是只断言 name 非空 |
| ③ | 抑制器**不覆盖检测器自己的视野** | 全局 `allow` 压掉被检测的信号 |

### 本轮三条链各断一条（全部主 agent 复核过代码行）

| 链 | 断在 | 实测 |
|---|---|---|
| `DeadCodeFitness` 死代码门 | **②+③** | `lib.rs:23` `#![allow(dead_code)]` 压掉信号；`test_all_have_names`（`nt_core_self_test_integration.rs:658-660`）**只 `assert!(!r.name.is_empty())`，丢弃 `.passed`** ⇒ 19 处违反映不出来 |
| `ArchLayer` 分层深度检查 | **①** | `nt_review_runner.rs:424-428` `read_dir` 后 `if ext != "rs" { continue }` ⇒ **目录被跳过** ⇒ `l0_substrate/`…`l6_meta/` 从不进入；喂真实目录列表实测**可分类文件 = 0** ⇒ `violations` 恒 0 ⇒ 无条件 PASS |
| `content_omitted` 变更省略 | **②** | Rust 侧三处 doc 声称「**UI 据此说**内容过大」+ DB 列 + TS 字段齐全 ⇒ **UI 渲染循环（`neobot-root.tsx:1979-1988`）零读点**；`rg '内容过大'` **只命中那两处 doc 自身** |

⭐ **最刺的一条**：那条「必须经本层 facade」的规则，
**就写在违反它的那个文件里** —— `l4_emotion/nt_feel_facade.rs:20-21` 写规则，
`:29` 违反规则（转出 L6 的 `EmotionLabel`），而门因 `check-layer-deps.sh:70`
排除 `-g '!*facade*'` **看不见**。

### ⭐⭐ 附带量级修正：同名检测器看不见「同机制、异类型名」

台账记 `CircuitState ×6`，实测同类**熔断器共 10 个** ——
因为 `BreakerState`、`CircuitBreaker`（类型别名）、包装类型都躲开了名字比对。
⇒ **任何「可归并 N 组」的数字都是下界，不是上界。**

## 元教训

本轮 7 条里，有 **4 条（L1/L3/L4/L7）的根因是同一个动作**：
**从一处证据跳到一个更大的结论。**

| 跳法 | 真相 |
|---|---|
| 「门开着」 ⇒ 记录可以含糊 | 门可宽，门框必须实 |
| 看见局部 `cursor` ⇒ 缺 resume | resume 已在队列表的 pending/completed 位 |
| 看见「预留」括注 ⇒ D-13 空着 | D-13 已占用，空位是 D-16 |
| 看见 `rg` 命中 ⇒ 模块叫 `n` | 是 rg 配置吞了标识符 |

⇒ **一般化**：**证据的粒度决定结论的粒度。**
一条 grep 命中只能支持"存在某个符号"，
**不能**支持"机制缺失""槽位为空""模块重名"这类**关于整体的**断言。

⇒ 而本轮四条真话，**全部是再读一次那一行 / 再列一次全部标题**得来的。
**成本极低，收益极高。**

## L9 ⭐⭐ 逆向推理的用法：**不抄工具，抄判据**

场景：用户要求「结合外部技术资料 + **从底层模型逆向推理**」。
风险有二：① 抄工具 ⇒ 违反 NTS-B10「parallel adapters are forbidden」；
② 抄判据 ⇒ 判据换了，数字必涨，多报即第二个误报门。

### 本轮的做法
外部 Rust 重复检测器（`find-dup-defs` / `cargo-dupes` / `dupehound` / `cddm` / `reDUP`）
**实现一律不抄**（我方已有 `scripts/ops/nt_dup_types.py`），
只取它们**默认开启的检测层**：

| 层 | 含义 | 我方现状 |
|---|---|---|
| Type-1 | 同名同体 | ✅ 有 |
| Type-2 | **改名**同体（alpha-renamed AST 规范化） | ❌ 无 |
| Type-3 | **改名 + 改写**同体（IDF 加权余弦 / L2AP simjoin） | ❌ 无 |

⇒ **Type-2/3 正是我方「可归并 258」低估约 40% 的根因。**

### ⭐ 逆向推理的那一步（真·从 LLM 机制推出判据）
不是「我想加 Type-2」，而是：

| LLM 机制 | → 架构治理判据 |
|---|---|
| 只有**同 token 序列**才能被同一模型高效处理 | ⇒ 只有**名字相同**才算重复 ⇒ 漏掉「改名同体」的机制 |
| **embedding 按语义而非字面** | ⇒ 应按**方法签名集合**聚类，而非类型名字面 |
| **MoE 靠 router 把请求分发给「能处理这类请求」的专家** | ⇒ 重复的判据应是「**谁能处理同一类请求**」 |

⇒ 落到一句可执行的话：`nt_dup_types.py` 的分组键
`(name, fields)` → `(method_signature_set, fields)`。

### ⛔ 必须同时承认的天花板（否则就是第二个误报门）
换判据 ⇒ 数字**必然上涨**。外部工具的共识做法是**先校准**：
`--calibrate` 出直方图 → 按 p50/p75/p90 定阈值 → 再定 severity。
⇒ **不改判据就是低估；改了不校准就是误报门。二选一都不合格。**
（本仓有前车：`check-term-viz` 336 误报后撤回过一次。）

### ⭐ 一条来自文献的反直觉教训
查「模块化 / 分层」时，同时搜到 Fowler《Monolith First》与 Tilkov《Don't start with monolith》
—— **两篇权威文章结论相反**。

⇒ 正确动作是**记录分歧**，不是挑一边当依据，也不是假装没看见。
（同理：ECSA 2017 实证「现有 code smell 工具不足以判定架构腐化」——
这恰好**解释了**本仓为何需要 50+ 人工裁决门，⛔ 别指望换个工具就免掉裁决。）

### ⭐ 一条定量天花板（来自 cs/0508023）
域熵 `H` 决定复用上限：最多复用 `(1-H)`；`H→0` 才是「强复用」。

⇒ 本仓 910,151 行代码的域熵**必然不低** ⇒ **「全仓强复用」不是可达目标**。
⇒ T1 各项的价值应按**局部 `H`** 估，不能按「消除重复的总行数」估。
⇒ 且实测我方**无 Shannon 度量**（`shannon|entropy_bits` 仅 2 处无关命中）⇒
按 D-16，**不该先做 `H` 的度量** —— 公理（§20）是它的前提，不是结果。

## L10 ⭐⭐ **同名不同轴**：先问"这个名字在本仓指哪条坐标轴"

第三轮做 Domain 轴错位时踩到的。

### 事故
`.neotrix/capability_registry.json` 每个节点有 `domain` 与 `layer` 两个字段。
我按字面理解 `layer` = 目录层（`l0_substrate`…`l6_meta`），于是去算 `layer × domain` 交叉表
—— ⛔ **整个前提是错的**。

### 真相（实测）
`rg 'l0primitive'` 全仓**只有 3 处命中**：枚举定义 `node.rs:145-158`、解析器 `roadmap.rs:63`、一张表。
⇒ **318 个节点里没有一个带目录层。**
registry 的 `layer` 是**第三条轴**（能力高度：`primitive → composite → orchestrator → autonomic`），
与目录层轴**正交**。

⇒ 所以「registry `layer`」与「目录层」**同名不同义** —— 正是 AGENTS.md L15
「**同名 ≠ 同一符号**」在**数据层**的形态（此前只在符号层用过）。

### ⭐ 可复用判据
给一个标识符建交叉表之前，先问：**它的每个取值，都能在本仓找到唯一定义处吗？**
`l0primitive` 找不到目录 ⇒ 它不是那条轴。
⇒ 反之 `domain` 是可靠的：枚举 `node.rs:9-21` 明确 11 个值，且与目录层近乎完美对角
（255/255 可解析节点只有 13 格偏离）⇒ **那才是真轴，而且是"穿了两个名字的一条轴"。**

### 附带：跨域重复对「按域分组」的检测器结构性不可见
`evolution.rs:427` 的嫁接检测 `acc.entry((n.domain, n.layer))` ⇒ 按 `(domain, layer)` 分组
⇒ **跨域的同 tag 永远进不了同一组**。
实测 `auto_fix` 双注册（`mind` 与 `repair` 两域，同 `l1composite`，**同 wiring_evidence 字符串**），
全库 14/742 个 `provides` tag 跨域 ⇒ **全部对该检测器不可见**，
而 `:414` 的注释自称「发现分散重复能力」。

⇒ ⭐ **这是 L8「绿色≠有效」的第三种形态**：
前两种是「断言被丢弃」「输入被跳过」，这一种是**「分组键选得恰好让问题落在组间」**。
⇒ 判据补一条：**一个检测器的分组键，往往就是它的盲区所在**。
