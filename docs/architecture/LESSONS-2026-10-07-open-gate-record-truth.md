# LESSONS 2026-10-07 —— 吸收开闸日：门开着，但**门框上要写清谁从哪儿来**

> 场景：用户令「**不要关 GitHub 的开源方式，只要给 URL 只管吸收，熔炼一切为自己的进化养料**」，
> 并当场贴 18 条记忆系统 URL。
> 这份记录的是**把门打开时不能一起拆掉的东西**，以及本轮真的踩到的坑。
> ⛔ 每条都是本轮实测，不是推理。

## L1 ⭐⭐⭐ 「吸收永不被开源阻断」≠「记录可以含糊」

用户要的是「门开着」。字面执行会顺手把**记录诚实**一起拆掉 —— 那正是本仓
`check-license.sh` 唯一守着的东西。

⇒ **本轮定的分界（NTS-B10.4）**：

| 可以放松 | 绝不放松 |
|---|---|
| 入参形式（裸 URL 即完整入参） | 记录的许可/来源**必须与事实一致** |
| 是否克隆、是否预批准 | **无 LICENSE ⇒ 只取设计，不取逐字代码** |
| 前置门答不出 → 不否决 | 门脚本的 deny 名单**不得为了变绿而删** |

⭐ **一句可复用的判据**：**门可以宽，门框必须实。**

### 本轮实证：这条界不是空话

`context_fs.rs` 第 1 行写着「基于 OpenViking 模式」，
而 **OpenViking 是 AGPL-3.0**（raw 实测）。
⇒ 我方**取的是模式（虚拟 FS），模式不受版权保护** —— 没抄代码。
但若记录只写「基于 X 模式」而不写「未取代码」，
**下一个读者会推断我方 vendor 了 AGPL**。

⇒ 该做的**不是删代码**（代码本就合规），是**让记录说清「模式来源 + 未取代码」**。

## L2 ⭐⭐⭐ 许可核实：主路径是 `raw`，不是 API

**实测**：GitHub REST API 匿名请求 **403 限流**（`API rate limit exceeded`）。
若就此下「许可未知」，18 仓里 **4 仓**会被误归为「无许可 ⇒ 不可用」。

⇒ 逐仓 × {main,master} × {LICENSE, LICENSE.md, LICENSE.txt, COPYING} 打
`raw.githubusercontent.com` ⇒ **18/18 全部拿到**。

### 三条连带教训
1. **默认分支 ≠ main。** `NevaMind-AI/memU` 的 LICENSE 叫 **`LICENSE.txt`**，
   在 `main/LICENSE` 永远 404。
2. **首行可能是空的。** Apache-2.0 正文首行是缩进 ⇒ `head -1` 得到空白，
   必须 `grep -v '^\s*$' | head` 再读。
3. **`❌ 无 LICENSE` 不等于「同一个结论」。** 它与 AGPL、与非商用**是三种档**，
   但处置**不同**：AGPL 代码层否决、非商用待商用确认、无许可只取设计。

## L3 ⭐⭐⭐ 「新增」占比畸高时，先怀疑检索不全

本轮 94 条机制：**72 强化 / 14 新增**。

而 14 条里有 **1 条被子代理判成「新增」，被主 agent 读现场推翻**：

| 子代理判 | 依据 | 实测真相 |
|---|---|---|
| `nt_crawl_sources.rs:556-567` 缺持久化 checkpoint，「无持久化断点续爬」判 **new** | 看见 `let mut cursor = 0usize` 是局部变量 | `cursor` 是**单次调用的尝试预算**（`cursor >= max_items * 4` 防毒丸死循环）；**持久化 resume 早已存在** —— `claim_hf_pending_url` 领 + `mark_crawl_complete` 落 |

⇒ **正确判定是「强化」，且那段代码本就正确。**
按判定表去"修"，就是把 bug 修进正确代码（对照 commit `9d7bdfa0` 同病）。

⭐ **一般化**：**判据是"新"的时候，是本会话最贵的断言。**
它要求穷尽性检索，而 `rg` 恰恰不给你穷尽性。
⇒ 凡要落"新"字，先问一句：**我搜的是符号，还是这个机制的**语义**？**

## L4 ⭐⭐ 卡位不可从单行括注推断

蓝图 623 行原写「（D-13 起为新增预留。）」，
我据此对用户断言「D-13 是空槽，可以占」。

⇒ **读全文发现 D-13 实为已占用的「能力补齐矩阵」（§16）**，
且该括注说的是**索引表预留行**，不是"卡不存在"。真正的空位是 **D-16**。

⇒ 与 AGENTS.md R-SCAN-1b 同型：**从一处命中跳到结论。**
**查证方式**：`grep -n '^## §'` 列全部节标题，一条就够。

⭐ **推论**：一个"这里什么都没"的断言，
和"这里有东西"一样需要证据 —— 而**不存在**比**存在**更难证。

## L5 ⭐⭐ 文档里引用的脚本会消失，判定门也查不出来

SKILL.md 长期把 `scripts/kb_batch_absorb.py` 当作「化为已有」的判定脚本。
**实测：不存在**（`absorb_to_capability.py` 同）。

⇒ 后果不是「脚本没了」，是**自动化降级为人工 grounding**，而文档仍写着
自动化口径 ⇒ 下一个 agent 会**凭关键词猜映射**（历史误映射率：知名大仓 ~16%、无名小仓 **68%**）。

⭐ **门为什么没抓到**：`check-doc-drift.sh` 只查 **root-doc** 的路径引用，
`skills/**` 不在扫描范围内（实测：它列出的 200+ 文件全是 `docs/` 与 4 个根 md）。

⇒ **失效机制**：判据所在的文档不在门的覆盖范围内 ⇒ 门对该文档的腐化**零敏感**。

## L6 ⭐ 「零读点」与「能力已建成」是两件事

本轮做了个选择：**没有**给 `free_energy` 造读点，尽管它是 D-16 的公理本体
（实测 `aif/` 袋外 **0 命中**）。

**理由是可核验的，不是"不方便"**：

1. 唯一现成落点需要新建 `AgentTrajectory` 平行适配器
   ⇒ **违反 NTS-B10「parallel adapters are forbidden」**；
2. 且 `ReasoningEngine` 持有的是 `traces: Vec<ReasoningRecord>`，
   **不持有** `AgentTrajectory` ⇒ 无数据源；
3. 无数据源的"接线"只会再造一个零读点字段。

⇒ 顺带查出同族两处：`compress_trajectory` 无生产调用方；
`compress_state_trajectory` 的 `level` 是**零读点参数**（三档输出恒等），
而 `seal_loop.rs:1077` 硬编码 `Medium`。

⭐ **诚实结论**：本轮真实的产出**不是** 14 个新能力，而是
**一张许可分档表 + 一条被推翻的判定 + 一批 intake**。
把「记下来」写成「接上了」，就是本仓最熟的那个病。

## L7 ⭐ 本机 `rg` 会吞掉标识符

`rg 'trajectory_compressor'` 的输出里，模块名被整体替换成字母 **`n`**：

```
use crate::l5_cognition::nt_core_trajectory_compress::{n, n};
pub mod n;          # 实际是 pub mod nt_core_trajectory_compress;
```

⇒ 一度以为全仓真有几百个叫 `n` 的模块。
加 `--no-config` 后恢复正常。⚠️ 吞标识符的配置来源**未查明**：
环境变量 `RIPGREP_CONFIG_PATH` 与用户级默认配置文件**均为空**
⇒ 生效配置**不在**这两个标准位置，**未定位**。
⇒ 未定位前，本仓凡要落 `file:line` 指控，一律带 `--no-config`。

⭐ **可复用判据**：**grep 的输出不是原文，就是证据。**
凡要落 `file:line` 指控，先用第二条路径复读那一行
（`grep`/`sed`/`read` 换一条），两者一致才算数。

## 元教训

本轮 7 条里，有 **4 条（L1/L3/L4/L7）的根因是同一个动作**：
**从一处证据跳到一个更大的结论。**

| 跳法 | 真相 |
|---|---|
| 「门开着」 ⇒ 记录可以含糊 | 门可宽，门框必须实 |
| 看见局部 `cursor` ⇒ 缺 resume | resume 已在队列表的 pending/completed 位 |
| 看见「预留」括注 ⇒ D-13 空着 | D-13 已占用，空位是 D-16 |
| 看见 `rg` 命中 ⇒ 模块叫 `n` | 是 rg 配置吞了标识符 |

⇒ **一般化**：**证据的粒度决定结论的粒度。**
一条 grep 命中只能支持"存在某个符号"，
**不能**支持"机制缺失""槽位为空""模块重名"这类**关于整体的**断言。

⇒ 而本轮四条真话，**全部是再读一次那一行 / 再列一次全部标题**得来的。
**成本极低，收益极高。**
