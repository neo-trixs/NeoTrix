> **「原子级拆解任何技术逻辑」+「复现他方产品」**。

## 0. 一句话结论

**NeoTrix 有「符号索引」，没有「调用图」。**
这一条缺失同时导致了本会话里几乎每一次判断失误，也正是「原子级拆解技术逻辑」
与「复现他方产品」两项目标**无法工具化**的根因。

## 2. 外部现状【外部】

检索到的公开资料在「给 agent 提供结构化代码上下文」这条路上已相当成熟。
按「与 NeoTrix 的相关度」排序：

| 项目 | 关键做法 | 与 NeoTrix 的差距 |
|---|---|---|
| **codegraph** | **委托给真实类型检查器**（TS 用 `scip-typescript`、Go 用 `go/packages`+VTA）拿 call edge，自称核心可证伪命题是「你不需要重写类型检查器」。只支持 Go/TS | 理念完全适用（Rust 侧对应 `scip-rust`），但本仓**一个类型检查器都没装** |
| **codebase-rag** | 符号级向量索引 + 引用图；**git blob-hash 做陈旧度审计**（确定性，非时间启发式）；`impact_of` 反向可达 | `impact_of` / 陈旧度审计 本仓没有 |
| **grafel** | 22 个 MCP 工具；**39 语言**；跨仓图；**消息总线拓扑**（topic/发布者/订阅者孤儿检测）；HTTP 面；流程追踪 | 本仓 11 个 workspace crate，**无任何跨 crate 边** |
| **awgraph** | AST+tree-sitter 调用图；诚实消融；指出 **GitNexus 是 PolyForm Noncommercial（禁商业使用）** | 许可意识本仓缺；awgraph 强调「不精确的边会误导 agent，宁缺勿错」 |
| **arXiv 2606.22417** | 受控因果消融（固定 harness 与模型，仅开关索引）。**最大收益在「改动跨 ≥3 个文件」这一档**；固定模型下结构化索引是**更低的 $/solved** | 直接命中本仓场景（第二棵树迁移、跨层搬迁都是跨多文件） |
| **ArchAgent** | 架构恢复：AST 引用图 + 自适应分段（DFS + 10% 邻组重叠）+ 跨仓上下文 + 业务对齐 | 本仓的 `CODE-TOPOLOGY.md` 只有**结构**，无**业务/意图**维度 |
| **Ry Walker 横评** | 17 个工具对比；强调**许可与隐私**（Serena 现为 GPL、GitNexus 禁商用） | 选型前必须过许可闸，本仓 `check-supply-iocs` 不覆盖这个 |

### 2.1 外部资料给出的三条可直接抄的判据

1. **委托，不重写**（codegraph）：把 call 解析交给已存在的类型检查器，
   不要自己用正则模拟类型系统。
2. **宁缺勿错**（codegraph / awgraph）：端点不是真节点的边**丢弃而不是猜**——
   「一个让 agent 信任的图，绝不能把 agent 送错方向」。
3. **一次编译 ≠ 可达**（arXiv）：引擎结果只是**指针**，
   路径要进入 agent 真实轨迹才算数；据此设计归因算法（View A/B）。

## 4. 核心建议（按杠杆排序）

### 建议 1（最高）：给 map 链路加**调用边**，且**委托 rustc 自己**

**做什么**：`nt_mapgen` 从「符号表」升级为「符号 + 边」。
边（`CALLS` / `IMPORTS` / `CONTAINS`）**不要用正则算**。

**为什么这是最高杠杆**：
- 一次性同时关掉 **G1 + G2 + G3 + G4**（其余三条都是它的下游）
- 它把「原子级拆解技术逻辑」从**技能**变成**查询**：
  「这段逻辑由哪些原子组成」= 查询可达子图；今天只能靠人读
- 它把「复现他方产品」从**checklist**变成**可计算**：
  「他方有的能力，我方有没有」= 「这个入口在我方可达吗」
- 外部受控消融（arXiv 2606.22417）表明：**跨 ≥3 文件的改动收益最大**，
  而本仓的主要工程动作（第二棵树迁移、层重构、跨 crate 搬迁）**恰好全在这一档**
- 本仓已有 82,835 符号的**成熟底座**，加边是增量而非重建

**技术路径（按「不重写类型检查器」原则）** —— ⛔ **本段已于同日实测，见
`CALLGRAPH-FEASIBILITY-2026-09-30.md`；原措辞过于乐观，此处只留结论：**
> 机制 ✅ 成立（本机 `RUSTC_BOOTSTRAP=1` 即可，**不需要 nightly**；
> `-Zunpretty=hir-tree` 的 `res: Def(Kind, DefId(crate ~ path))` 即编译器自己的解析，
> 4,858 行实测 34,478 处，同名诱饵结构上不可能）。
> ⛔ 但**未证**的是「把它变成边表」：文本传输 31 KB/源码行 ⇒ 全树约 27 GB，
> 且我的行级正则抽取器实测 #CALLS 0（找错字段，不是没有边）。
> ⇒ 需要真正的解析器 + 更紧凑的传输（`.rmeta` 或 rust-analyzer 索引）。**这是主要工作量。**

原路径草案（保留供追溯，**已被上述实测取代**）：
1. ~~先探 `cargo +nightly rustc -Zunpretty=…`~~ —— 不需要 nightly
2. 若不可得 → 走 `scip-rust`（对应 codegraph 的 `scip-typescript` 路线）
3. 再退一步：`syn` 解析 + **显式标注「未解析边」**（照抄「宁缺勿错」判据，
   绝不猜边）

**判据（可证伪）**：加边后，`nt_locate --callers <symbol>` 对
**今天被 grep 骗过的 3 个案例**（花括号导入的 `CapabilityTreeRegistry`、
同名诱饵 `CrystalCycle`、feature 门控后的 `Outlet` 字段）必须**全部答对**。
答不对就是边没建对，不是检索没调好。

### 建议 2：吸收流程补两个工具 + 一个度量

- **拆解器** `nt_decompose`：把外部技术条目切成**原子能力单元**
  （每单元 = 输入/输出/前置条件/失败语义/可验证判据），落成机器可读 YAML
- **存活率** `nt_absorption_live`：对每个已吸收单元查「今天是否可达」
  （**依赖建议 1 的边**；G5 的直接解法）
- **许可能入** `check-license.sh`：吸收外部代码时过 SPDX 与使用限制
  （`PolyForm Noncommercial` 这类**禁商用**许可必须硬拦）

**判据**：`nt_absorption_live` 跑一次应当复现出今天已知的 212 个死文件
量级 —— 若它报「全部存活」，说明判据无效，不是仓库健康。

### 建议 3：map 从「结构」升到「意图」

`CODE-TOPOLOGY.md` 现在只有结构（树/层/密度）。借 ArchAgent 的思路补两个维度：
- **入口图**：哪些符号是生产可达的入口（今天靠 `coverage-gaps` 的 advisory 猜）
- **意图对齐**：每个模块的 doc 承诺 vs 实际实现
  —— 今天已抓到 1 例：`nt_core_reasoning.rs` 删了 `ContextBuilder` 而其 doc 仍承诺
  「提供 KB/经验 → Kernel context 自动注入」

### 建议 4：**不要**做的事（避免把门建在流沙上）

- ⛔ 不要给「死代码」建门 —— 工具自述不可靠（G7），门会立刻失去可信度
- ⛔ 不要用正则猜 call 边 —— 违反「委托，不重写」与「宁缺勿错」
- ⛔ 不要在本轮并行做建议 1 + 建议 2 的全部 —— 建议 2 依赖建议 1 的边

## 5. 立刻可做、零依赖的三件小事

1. **把 `rg -E` 地雷写进 `AGENTS.md`** —— 本会话实测：`rg -nE '…'` 在本机
   **任何模式都静默返回 0**（`rg: error parsing flag -E: … unknown encoding`），
   而 `rg -n '…'` 正常（`D-[0-9]{2}` 在蓝图里 87 vs 0）。
   我本会话的 `2>/dev/null` 习惯把错误吞成了「零命中」——
   **这正是「零命中不是零消费」那条纪律被工具层面绕过的一次实例。**
2. **检查本会话是否有结论建立在 `rg -E` 上** —— 结论：两处用了 `-E` 的地方
   （蓝图标题）**恰好都是我没下结论、直接读文件的地方**；门的实现用 Python `re`，
   不受影响。⇒ 侥幸，不是设计。
3. **`check-ci-refs` 增加一项**：门脚本里引用的外部命令必须**实测可执行且支持所用 flag**，
   零命中不得默认当作「通过」。
