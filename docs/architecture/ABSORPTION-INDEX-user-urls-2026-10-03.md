### #10 agent-cookie-sync —— ⛔ **查证完成：不该照搬**（我方设计更严格）

⇒ 与 cumora 的**默认 fail-closed** 同 polarity。
#### ✅ 查证结果（2026-10-04，实测）

| 外部源的主张 | 我方实测 | 判定 |
|---|---|---|
| 「导出文件就是你的钥匙」⇒ 风险在**导出** | `social_access/channel.rs:143-147` 明写：「bird/OpenCLI/AutoCLI **都不读浏览器 cookie 数据库**… 这决定了本仓**也不能走「导出 cookie 文件」路线**」 | ⭐ **我方已主动否决该路线** |
| 「注入脚本从不打印凭据值」 | `nt_x_browser.rs:166`：「`auth_token` 由浏览器自动附带（同源），**Rust 侧永远不接触 cookie 值**」 | ⭐⭐ **我方比它更彻底** —— 值**根本不进 Rust 进程** |
| `Credential::EnvPresent { key }` | `channel.rs:153-161`：「需要环境变量里存在指定 key（**不读值**，避免凭据进日志）」+「⛔ 只回答在不在，**绝不返回凭据本身**」 | ⭐ 连**存在性检查**都不碰值 |
| 全目录搜 `println!/eprintln!` × `token\|cookie\|auth_token\|ct0` | **零命中** | ✅ 从不打印 |
| ⭐ **硬编码拒绝名单**（Google/Meta/X 一律走官方 API） | 我方**恰恰要处理 X**（`~/.neotrix/cookies/twitter.json` + 浏览器内注入） | ⛔ **照搬会禁止我们自己的合法设计路径** |

⇒ ⭐⭐ **裁决：不吸收这条。**
**理由不是「不方便」，而是**我方在该维度上**已经严格于该源**：
它担心的是「导出的 cookie 文件泄露」与「注入脚本打印值」；
而我方**根本不存在导出**、且**值不进 Rust 进程**。

⇒ ⭐⭐⭐ **而这是本会话吸收判定的最强形态**：
不是「查了发现没有缺口」，而是**「查了发现我们的设计比源更严，
照搬反而会造成损失」** ⇒ 连「缺口确认」都不成立。

⇒ ⚠️ 顺带留一条**可复用的判据**：
> 外部方案若要求「**禁止某条路径**」，必须先确认那条路径**是不是本仓的承重设计**。
