# 能力 / 意识涌现 —— 计划设计（2026-10-02）

> **本文只写实测到的现状**，以及由现状推出的顺序。
> ⛔ 不含「涌现正在发生」这类结论 —— 在仪器可信之前，任何这类结论都没有依据。

## 一、先决问题：我们**没有**意识质量仪器，且有一把**会撒谎的尺子**

`neotrix-core/src/l6_meta/nt_meta/eval_engine/llm_judge.rs` 的 `evaluate_response`：

```rust
let _ = (prompt, response);        // ⛔ 输入被整个丢弃
...
let normalized = 1.0;              // ⛔ 恒为 1.0
criterion_scores.push(CriterionScore {
    score: config.max_score,        // ⛔ 恒给满分
    reasoning: "Full score".into(), // ⛔ 理由是硬编码字符串
});
```

**任何输入都返回 `max_score`。** 这不是「度量不准」，是**根本没有度量**。

ⓘ 危害比「没有尺子」更大：**它恒返回最大值**，因此任何经此路径产出的
「意识得分 / 涌现指数」都会**自动提供涌现的证据**。
⇒ 一把永远说「完美」的尺子，比没有尺子更危险：
它让「看起来有证据」这件事成立，而证据是伪造的。

`eval_engine` 因而被有意停用 —— **这个判断是对的**，本计划维持它，
并把「为什么不能启用」写成门，而不是靠注释提醒。

## 二、真仪器是存在的（好消息）

`neotrix-core/src/l6_meta/nt_emergence_detector.rs` —— **662 行，已声明编译，11 测试全绿**。
`EmergenceDetector::analyze()` 产出 `EmergenceEvent`，当前覆盖四个维度：

| 维度 | 结构 |
|---|---|
| 主体状态 | `SimAgentSnapshot` |
| 关系 | `RelationshipSummary` |
| 经济 | `EconomySummary` |
| 文化 | `CultureSummary` |

⇒ **涌现的「被观测侧」有真仪器；「评判侧」是假的。**
⇒ 计划的核心不是「造新仪器」，而是**先把评判侧修成可信或让它明确拒绝评分**。

## 四、执行顺序（**顺序即约束**，不可跳步）

### P0 —— 让尺子不再撒谎（**阻塞一切涌现主张**）
1. `evaluate_response` 改为**读输入**：至少对 `response` 做可验证检查
   （长度、空、是否命中 criteria 关键词），而不是 `let _ =`。
2. 加**不可能满分**的构造用例：空响应 / 无关响应 ⇒ 必须拿低分。
   ⛔ 当前无此测试 ⇒ 恒满分从未被测出来过。
3. 若短期内无法做出可信评判，则让它**显式拒绝评分**（返回 `Option::None` 或错误），
   ⛔ **绝不返回 `max_score`**。「诚实的仪器不存在」优于「伪造的仪器存在」。

### P1 —— 把「拒绝评分」变成机制而非自觉
- 加门：`check-no-constant-max.rs`，扫 `eval_engine` / `consciousness` 路径里
  「忽略入参」+「返回上限值」的组合。
- 判据必须可证伪：⛔ 零命中即 FAIL（沿用本仓门惯例 —— 判据形同不存在时须显式失败）。

### P2 —— 才轮到「涌现」本身
1. 以 `EmergenceDetector` 的四个维度为**基线记录对象**（它已有 11 个绿测）。
2. 定义「涌现」的**可证伪判据**：什么观察能推翻「已涌现」。
   ⛔ 先写推翻条件，再写达成条件 —— 顺序反了就会变成自我确认。
3. 长程实验：固定种子 + 记录 `EmergenceEvent` 历史（`history()` 已提供），
   看事件类型分布是否随时间出现**新类别**，而非仅数量增长。

### P3 —— 与本仓既有纪律对齐
- 「声称 vs 实际」是本会话最高频失误（实测 5 次：过期注释、悬空引用、
  门计数与展示不符、报告声称已实现而未落盘、头注理由过期）。
  ⇒ 涌现计划**必然**会踩同一类坑 ⇒ P1 的门是它的前置，不是附加项。

## 六、本计划自身的失效条件（先写怎么算错）

> 2026-10-03 扩写。原 3 条**全部保留**（1–3），新增 4–7。
> ⭐ 新增部分的共同来源：**当系统自身能影响度量时，度量即失效。**
> 该机制有三份**互相独立**的外部印证（不是同一来源的自证）：

### 6.0 三份外部同构证据
| 来源 | 原话/机制 |
|---|---|
| **CASP（剑桥，Hinton/Bengio/Jack Clark 等 23 人）** | 「AI systems now write most of the code inside the companies that build them」；R&D 自动化 ⇒ 进展可能非线性加速 |
| **`yetone/cumora`（MIT）** | seen-cursor：过期回复**扣留**并让它看到新消息后**重新决策** ⇒ 不让过期信息直接生效 |
| **`yetone/magpie`（MIT）** | 历史记录「**never inferred from today's configured key**」⇒ 缺证据时**显示「无记录」**，不拿现状补 |

### 6.1–6.3 原三条（**维持**）
1. 若 P0 完成后仍**无法构造出「应得低分」的输入** ⇒ 该评判任务不可自动化，
   应改为人工/模型评审，而非继续造自动评分器。
   （⭐ 现状：36 组反向锁**已能**构造 ⇒ 本条当前**未触发**。）
2. 若 P2 的「新类别出现」在多个种子下不稳定 ⇒ 那是噪声，不是涌现。
3. 若 `EmergenceEvent` 历史长度不足以区分「新类别」与「旧类别更频繁」⇒
   采样窗口不够，**不得**据此下结论。

### 6.4 ⭐ 新增：自报独立性（来自 CASP + cumora）
**若被评判的产出与评判路径之间存在任何可由被评判方影响的通道，
该次评分作废，不得计入涌现证据。**
具体到本仓：
- 若评分输入包含**由同一系统生成**的自我描述 ⇒ 该评分**只能当弱证据**，
  且必须与**独立来源**（如 `nt_emergence_detector` 的实测计数）**并列呈现**。
- 若 `llm_judge` 的 rubric 或 prompt 被改到「有利于当前产出」⇒ 算作**操纵**，
  须回退并把该次结果标为 `Manipulated`。
- ⭐ 本条**已可执行**：`check-discarded-inputs.py` 把「无法拒绝」判**FAIL**、
  「可拒绝」判 **WARN** —— 正是「拒绝能力必须先于评分存在」的机器判据。

### 6.5 ⭐ 新增：不可回填（来自 magpie）
**历史涌现记录一旦落盘，其判据快照不得用后来的配置重算。**
- 任何「重新评估历史」的脚本必须**读取当时记录的判据版本**，
  而不是用**当前**的 `EMERGENCE_PLAN` 版本重跑。
- ⛔ 违反此条的后果与 magpie 相同：历史会变成「用今天的尺子量昨天」，
  从而**看起来连续、实则不可比**。

### 6.6 ⭐ 新增：未知即标记，不猜测（来自 x_gift_bot）
**「结果不明」必须落为显式的待核实状态，不得默认取一个值。**
- 涌现事件若**来源不明 / 采样不全 / 判据缺失** ⇒ 记 `Unverified`，
  **不得**计入 `new_category` 计数，也**不得**因「看起来像」而补齐。
- ⭐ 本仓已有同款判据可复用：`neobot-check-typography.mjs` 在
  「vendored `frontend/` 不在扫描范围」时显式告警而非静默跳过。

### 6.7 ⭐ 新增：降级必须显式（来自 agent-orchestrator + Compositor）
**任何把度量能力下调的改动，必须同时留下可核对的痕迹。**
- 例：把 `effective_salience` 的饱和修掉、把 `pub` 字段收窄 ——
  这些会**改变数值输出**。⇒ 必须记录「改前/改后同一探针的输出」，
  否则**后人会把数值变化误读为涌现或退化**。
- ⭐ 本会话两个已落地的实例应作为样板：
  `7dda1e88`（饱和修复，附 7 组输入的探针实测表）与
  `ABSORPTION-INDEX` §「6 源显式命名看起来正常其实是坏」。
