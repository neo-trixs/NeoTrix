# 教训：白屏排查与 Tauri 资源内嵌陷阱 — 2026-09-28

> 本轮从「打开空白界面」查到根因的全过程。最贵的一课不是某个 bug，
> 而是**连续三次用不可靠的判据下结论**，每次都是事后才发现判据本身无效。

## L1. Tauri `devUrl` 配了，release 构建内嵌零前端资源

**签名**：窗口正常弹出、有标题有尺寸、无任何报错输出、进程存活 —— 但纯白。

**根因**（tauri-codegen 2.7.0 `src/context.rs:178`）：

```rust
} else if dev && config.build.dev_url.is_some() {
  let assets = EmbeddedAssets::default();   // ← 空的
}
```

只要配了 `devUrl`，`dev && dev_url` 分支就触发 —— **连 release 里 `dev`
也是真**（`is_dev()` 读 `DEP_TAURI_DEV`，在本机 release 构建中恒为真；
是环境问题还是 Tauri bug，未查明）。于是内嵌零资源，webview 无物可载。

**验证方法（确定性的，不依赖字符串搜索）**：
release 构建对 brotli 压缩资源，`strings` 搜不到属正常 —— 别拿它当证据。
改用**二进制大小对照**：空 `dist`（1KB）vs 满 `dist`（200KB+）构建，
若字节数分毫不差（本轮实测都是 22921120），则前端根本没进去。
删 `devUrl` 重建后 +49,536B（正好是 brotli 压缩后的前端体积），即修好。

**修法**：`tauri.conf.json` 里 `devUrl` 置 null。代价见下。

**代价与替代方案**：`tauri dev` 工作流需要 dev server。替代方案是
`TAURI_CONFIG` overlay 或临时加回，不影响 release。不要为了 dev 方便
把 devUrl 留在提交的配置里 —— 留一次，白屏一次，且**无任何报错提示你**。

**为什么难查**：Rust 侧一切正常（进程活、无 panic、零输出），前端代码
一行错都没有（tsc/vite 全绿）—— 因为前端**从来没被加载过**。
所有「前端有没有错」的检查都是空转。排查时先问「资源进没进二进制」，
再问「代码对不对」。顺序反了就会绕大圈（本轮就绕了）。

## L2. 判据必须先自证有效，对照实验要在结论之前做

本轮三次栽在同一个地方，模式完全一致：**用间接信号下结论，事后才发现
信号本身无效**。

| 我说的 | 实际 | 缺的对照 |
|---|---|---|
| 「DB 没被碰 → 前端没跑」 | SQLite `SELECT` 是只读，**不改 mtime** | 先对已知能跑的路径测一次，看它改不改 mtime |
| 「lsof 没打开 db → 前端没跑」 | `open_store()` 每次开→查→关，采样时已关 | 同上 |
| 「文件快照 0 变化 → 前端没跑」 | 做了对照才发现：已知能跑的 HTTP 路径**也是 0 变化** | 对照本应在下结论前做，不是在被质疑后 |

**规则**：任何「A 没发生 → B 没跑」的推断，必须先在**已知 B 在跑**的
环境里验证「A 会发生」。否则这个判据是装饰品。顺序是：先证判据有效，
再用判据下结论。写下来是因为每次都觉得「这次很明显，不用验证」——
而每次都是那次翻车。

唯一验证过可靠的通道：**让被测对象自己经 IPC 把状态写出来**
（本轮是 `neobot_fs_write` 写 JSON）。它不依赖采样时机、不依赖文件
语义，一次就拿到真相。优先用它，而不是从外部猜。

## L3. 一个缺失的元素能把整个应用打瞎

`main.ts:959` 顶层执行 `($("head-search") as HTMLButtonElement).onclick = …`，
而那四个元素在 `index.html` 里一个都没有（功能代码完整，HTML 从没写过，
且仓库只有一个建仓提交——**从第一天起就是坏的**）。

`$()` 把结果断言成 `HTMLElement` 不做 null 检查，于是 `null.onclick`
抛 TypeError，**把整个模块中断**：后面 40 多个 id 的初始化、侧边栏挂载
（1189 行 + TabRegistry + 5 个页签**从未挂载过**）全不执行。

症状极具误导性：不是「搜索按钮没反应」，而是整个界面半残，且**零报错
到 stdout**。排查时先怀疑了 dev server，绕了一大圈才用「让页面自己汇报
DOM」的办法定位。

**门**（已落地，`nt_commands.rs` 的 `registration_tests`）：
`every_toplevel_dom_id_exists_in_index_html` —— 只查**顶层（未缩进）行**。
函数体内的缺失只影响一个功能；`html +=` 拼出来的动态 id 本就不在静态
HTML 里；有 `?.` 的视为已兜过。顶层则不同：那里一旦抛错就是模块级，
后果是整个应用半残。

**第一版这道门是空转的**：用 `starts_with("$(\"")` 过滤，而实际行首是
`const` 和 `(`，什么都没匹配到，两次变异都「通过」。教训是 L2 的实例：
门写完必须立刻变异测试，**红不了的门等于没有门**。

## L4. 状态组合必须显式枚举，缺一个就是一个空白

`.body` 的 4 列 grid 有 `no-right` 去掉 info 列，却没有任何规则去掉 sb 列。
sb 关掉时那 460px 的第 4 列还在 —— 里面是空的但位置占着（「收起了还占用」）。

四种组合（info 开/关 × sb 开/关）缺了两种。本次按既有模式补齐，
特异度已验算（`no-right:not(.sb-open)` (0,3,0) > 两者 (0,2,0)，后写赢平级）。

**规则**：凡是 N 个二元开关决定的布局/状态，提交前把 2^N 种组合列出来，
逐个确认有规则覆盖。N=2 时就是 4 行，写下来只要一分钟；
不写下来，缺的那种组合就是用户看到的 bug。本轮还附带一处：
`collapseRight` 只去 grid 列、`#info` 本体还渲染着掉进隐式行 ——
**可见性与布局必须同步改，只改一边等于没改**。

## L5. 小坑（各一行，免得下次再踩）

- **`sed 's/^/  /'` 的显示前缀会污染缩进判断**。屏幕上的缩进比文件多 2 格，
  据此写的替换锚点连续失败两次（`paintEditor` / switch 的 `case`）。
  判断空白必须用 `cat -A`、`od -c` 或 python `repr`，不用肉眼。
- **`grep -c` 单文件时不带 `file:` 前缀**，`awk '{s+=$2}'` 会取到空串。
  本轮因此两次误报「0 处」（bundle 落地检查、类型表覆盖检查）。
- **Rust 内联格式参数不支持表达式**：`format!("{n + 1}")` 会被当成字段名
  `n + 1` 而编译失败。先算进变量再用。
- **bash 会把紧跟变量名的全角字符吸进变量名**：`"…$n_i，位于…"` 报
  `n_i?: unbound variable`。一律写 `${n_i}`。`set -u` 能抓住它，
  否则静默取空值。
- **`format!` / `assert!` 的消息里别放未验证的断言**，尤其是从变量拼的。
- **变异测试要覆盖门本身**，不只覆盖被测代码。本轮三次抓到门空转
  （jail 测试、抽取器、toplevel-id 门第一版），每次都是门写完自以为
  有效，变异一跑才发现是摆设。
