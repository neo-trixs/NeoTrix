## ⭐ L1 「显示层加装饰、解析层不剥」= 可复制性缺陷（本轮最可推广的一条）

**现象**：上窗那一行是 `format!("  [{}] {}：{}", d.id, …)`（`nt_crystal_dialogue.rs`）
⇒ **屏幕上带方括号**；而解析层四条 arm（`ok ` / `no ` / `<id>!` / `<id>:`）都把
`[id]` 原样存进 `demand_id`，与需求单真实的裸 id 比对不上
⇒ **用户照抄自己看到的东西永远不成立**，`ntcode --line` 死锁在同一道复核门。

**三次实测**：
```
ok [review-fc47da46]     →  round2 内需1项已上窗  →  Stalled    exit 2   ✗
[review-fc47da46]: 收到  →  round2 内需1项已上窗  →  Stalled    exit 2   ✗
ok review-fc47da46       →  内需清空，收敛         →  Converged  exit 0   ✓
```

**修法必须是「容忍」而不是「报错拒绝」**：加括号的是**显示层**，真实 id 永不含括号
⇒ 把屏幕上那个合法字符串判成非法输入，是把用户的**合理操作**报成错误。
所以解析层剥掉**成对**外层括号，裸 id 走原路径，两种输入都成立。

**推广判据**：任何「渲染时加了装饰」与「解析时按原文比对」的配对，
都要问一句「用户照抄屏幕能不能过」。**报错不是兼容性，是把 bug 转移给用户。**

## ⭐ L2 硬编码的**资源标识**会漂移，而现有门全都管不到

`ntcode.rs` 的 `const FALLBACK_FREE_MODEL = "opencode/mimo-v2.5-free"` ——
实测 `opencode models | grep -c 'mimo-v2.5-free$'` = **0**，已下架；
活的是 `mimo-v2.6-flash-free`。⇒ 「池里没有免费模型」时的**最后手段必然打空**。

⛔ `layer-deps` / `feature-gates` / `claims-numbers` / `truth-surface`
**全都看不见这类漂移** —— 它们管的是结构与文本，⛔ 不管「这个字符串今天还有效吗」。

**处置**：改值 + 把**复核方式写进注释**（`opencode models` 跑一遍对比本常量）。
⛔ **故意没有立门**：CI runner 上没有 `opencode`，立一个联网判据 =
「报 PASS 却结构上不可能失败」的空门（L8）；立一个离线清单门 = 清单自己也会漂。

**推广**：硬编码常量分两类 —— **结构常量**（类型名/字段名/层名，仓内可判定 ⇒ 门能管）
与**资源标识**（模型 id、URL、端点、外部服务名 ⇒ 只在运行时有效）。
⛔ 别用前者的门去覆盖后者。

## ⭐ L3 并发工作树里，**编译错误可能是中间态而不是缺陷**

11:47 我跑 `cargo test` 抓到 `external_cli_plugins.rs` 一个 `E0308`
（`Arc::clone` 类型不匹配）。读现场后：**那窗口正在给 `CliDescriptorPlugin`
加 `shared_handle()`、把 `descriptor` 从 `ExternalCliPlugin` 改成 `Arc<…>`** ——
我的编译**抢跑到了它的中间态**。文件随后静止 60 秒。

⛔ **没有去"修"它** —— 那会把 bug 引进别人即将完成的正确代码
（这是 2026-09-27 那次「按单修告警」的同一个陷阱，只是这次触发器是编译器而不是扫描器）。

**推广**：并发工作树里，⛔ **任何**来自编译/扫描器的告警都要先问
「这个文件此刻的 mtime 距今多久」。**距今 < 60 秒 ⇒ 是中间态，不是缺陷。**

## ⭐ L4 编译器说 `FAILED`，先分清是**断言错**还是**实现错**

`--bin ntcode` 一条测试红了：`--agent-arg 的值必须原样收下`，
`left: ["--model"] / right: ["--model", "x/y"]`。

读实现：`"--agent-arg" => { i += 1; agent_args.push(argv[i]) }` —— **单值 flag**，
与 usage 承诺的 `--agent-arg ARG`（示例还写了两次出现两次传参）**一致**。
⇒ 是**测试自己错**：它要求 `--agent-arg` 贪心吃两个元素。

⇒ 修的是断言，不是实现。**断言写错比实现写错更贵** —— 它会让人去改对的代码。

## ⭐ L5 同一测试里出现**互相矛盾**的两条断言 ⇒ 解法是消除输入歧义，不是二选一

我按真实契约把断言改成 `goal == "x/y"`，对方几乎同时在**我的断言后面**追加了
`goal.is_empty()`。两条同时存在、必然一红。

⛔ **两条都不能删**（都不是我的），⛔ 二选一也是在赌。
正解：**改输入让歧义不存在** —— 两个值都用 `--agent-arg` 显式传、一个裸词不留：
`--agent-arg --continue --agent-arg 2026-10-07T11-53-48.313Z`。
此时 `goal` 必须为空、`agent_args` 必须按序收齐 ⇒ **两条断言同时成立**，且各自都能红。

**推广**：断言冲突往往不是「谁对」的问题，是**测试输入同时踩了两条契约**。
先改输入，再谈断言。

## L7 客户端的「关广告」开关可能是**被构建期常量短路的死开关**

freebuff 的 `settings.json` 里 `adsEnabled: false`，`/gravity disable ads`
还会回执一句「Ads disabled.」—— **文件和回执都是真的，行为是假的**。

字节偏移量实证链（86 MB 的 Mach-O）：
| 步 | 原文 | 偏移 |
|---|---|---|
| 1 | `LR=()=>({...nP(),SystemRoot:process.env.SystemRoot,…})` | 62751573 |
| 2 | `CODEBUFF_TRUST_AGENT_DIRS:process.env.…` | LR+**1966** |
| 3 | **`FREEBUFF_MODE:"true"`** | LR+**2030** |

⇒ 同一个对象字面量里，邻居全是 `process.env.X`，**唯独 `FREEBUFF_MODE` 是硬编码字面量**
⇒ `QA = LR().FREEBUFF_MODE === "true"` 恒真 ⇒
`adsEnabled()` 在 `if (QA) return true` 处短路 ⇒ **配置文件永远读不到**。
⛔ 环境变量也救不了：`LR()` 是**白名单式** env，不整体展开 `process.env`。

**推广**：「设置里有个开关」**不等于**「它被消费」。判据是**唯一真源**（二进制/真源文件），
⛔ 不是配置文件里那个值。**回执文案尤其不可信** —— 它证明的是「写进去了」，不是「生效了」。

## ⭐ L9 `git commit --only` **挡不住**别人把你扫进他的 commit

我按 AGENTS.md §1 用 `git add <4 个新文件> && git commit --only <12 个文件>` 提交，
结果 **11 个进了 `8774ed2f`**；缺的那个 `scripts/gate-registry.tsv`，
`git log -S` 显示**我加的那一行早在 `c8b55e54` 里了** ——
而那条 commit 的题是 `fix(gate): check-naming 从「恒红且默认报绿」改为递减棘轮`，
**是另一个窗口关于另一个主题的提交**。

⇒ 内容没丢（这点是幸运），但**归属错了**：一条 gate 登记被记在了不相干 commit 的名下。

**推广**：`--only` 保护的是「**我不要**提交的东西」，⛔ 保护不了「**我的东西**不被别人带走」。
共享 index 下，⛔ 提交后必须 `git log -S '<我独有的字符串>' -- <我改的文件>`
逐个自查归属 —— 这是唯一能发现「被顺带提交」的手段。
