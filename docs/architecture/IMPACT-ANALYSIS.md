# 蓝图实施影响面分析 (SIM-26 机测)

> **Date**: 2026-09-21 | **Baseline**: 全域审计快照 (2191 文件/~719k 行) | **Status**: 评估，非执行
> 结论一句话：广度中等（约 5–8% 文件被触碰），风险集中（<10 个行为点决定成败）。

## 2. 三个真正的风险点（按严重性）

### RISK-1: SDB fail-closed 可能打断正在工作的 agent 回路 (P1-03)
Verifier 写错＝误拒＝活功能变砖，比越层本身更危险。
缓解（本分析新增要求）：每个站点先 **log-only 烘焙**（verifier 跑、分不出手），
误拒率达标后再翻转 fail-closed。翻转需逐站点 ADR，不得批量。
→ ROADMAP P1-03 需追加此句（P-task）。

### RISK-2: 百文件级 import churn (P1-02＋P2)
类型下沉与模块拆分本质是大规模改路径。靠一条纪律兜底：
**re-export 别名保留一周期**，删别名前必须零引用（机验）。
违反此条的一次性改路径＝全仓红。

### RISK-3: 验证能力跟不上改动规模
本机 OOM 跑不完 `--tests`；P2 百文件改动本地不可全验。
含义：P1-02/P2 期间 **CI 是唯一的真门**，本地只做 `check --lib` 冒烟。
任何"本地过了"的声明在此期间自动降级为"部分验证"。

## 3. 不可逆点清单（动之前先写回滚）

| 点 | 回滚手段 | 缺失即不做 |
|----|---------|-----------|
| 存储格式变更（记忆拆分） | 版本化＋可回读上一版 | P-task 验收项 |
| Facade 公开接口删除 | deprecated 别名一周期 | NTS-B02 已有 |
| 阈值门翻转（覆盖/基准/SDB） | ADR 豁免回退 | NTS-D04/D05 已有 |
| SDB fail-closed 翻转 | 逐站点回退开关 | 本分析 RISK-1 新增 |

## 4. 并发与环境现实

- 协作者并行编辑中（Shimmy 臂、crystal 文件皆他人手笔）：P1-02/P2 动 gateway/memory
  前必须先同步，小步＋快合入，避免大 MR 撞车。
- 100 文件 cli 删除先例证明团队能接受大删除——但那是删死代码；
  P2 动的是活代码，标准不同，不可类比放行。

## 5. Go / No-Go 建议

- **GO（分阶段）**：P0、P1（除 SDB 翻转外）、P3、P4 按既定计划走。
- **CONDITIONAL**：SDB 每个站点必须经过 log-only 烘焙＋独立 ADR 才翻转；
  P2 拆分必须带别名过渡＋CI 全绿。
- **NO-GO**：一次性全量改路径；无基线的阈值门；跳过登记的 SDB。
