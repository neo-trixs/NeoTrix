# O-1 裁决：agent_loop 能力差集（2026-10-06，纯只读比对）

## 结论：**不是重复，不能按「被取代」删除** —— 但也**不该直接接线**

上一轮我推荐「删除（被 L1 原件取代）」。**能力差集推翻了这个结论。**

## 差集实测

`agent_loop` 的功能面（`trait_.rs`）是完整闭环：
**plan → execute → verify → adapt**，外加 **auditor** 与 **task manager**。

编译树内三个后继者实测：

| 位置 | 类型 | 动作面 | 判定 |
|---|---|---|---|
| `nt_io_agent_loop`（**已编译**） | `AgentLoop` `ToolInvocation` | **仅 `execute`** | 同名不同物|
| L0 `nt_core_traits::AgentExecutor` | — | `execute / interrupt / status / capability` | 是「可中断执行器」，**非闭环** |
| `neobot::nt_agent::run_loop` | — | 单轮 `for` 推进 `TurnStatus` | **无 verify / audit 环节** |

**编译树内完全不存在的**（实测 grep，排除 agent_loop 自身）：

- `trait AgentAuditor` / `trait Auditor` ⇒ **0 处**
- `struct AgentPlan` ⇒ **0 处**
- `CrossVerification` ⇒ **0 处**
- `fn verify` / `fn adapt` 的命中**全是同名无关物**
  （`verify_db_schema` / `verify_draft_tokens` / `channel_adapter`）

⇒ **「计划 → 验证 → 修正 → 审计」这一层在编译树里确实不存在。**
`neobot` 也**零引用** `AgentPlan`/`AgentAuditor`/`CrossVerification`/`LoopConfig`。

## 所以它是什么

| 判定 | 依据 |
|---|---|
| **不是** agent_loop 的重复副本 | 能力差集非空（verify/adapt/audit 层在别处没有） |
| **不是** 死代码 | 2,096 行 + **31 个测试**（有人维护过） |
| **是** 「有能力、无接线」的第三类 | 既未被取代，也未被使用 |

⚠️ 这修正了我前两轮的判断链：先说「被 L1 原件取代 ⇒ 删」，
被`#[path]` 假阳性纠正过一次后，又被「同名即重复」误导 ⇒ **现改为以上结论**。

## 最优解：三选一，但**必须先答一个前置问题**

前置问题（决定其余全部）：
**「计划 → 验证 → 修正」这一层，本仓是否要？**

| 选项 | 动作 | 代价 / 风险 |
|---|---|---|
| **A. 不接线，直接归档**（推荐） | 移入 `_archive/`（仓内已有此惯例），或在完成一次能力评估后删除 | 保住31 个测试作为**可复活资产**；风险最低。⚠️ 代价：若将来要「每次动作都验证」，得从这里取回 |
| **B. 接线** | 在 `nt_io_agent_loop` 或 neobot 生产 loop 上挂 verify/audit | 收益：动作可验证。⚠️ 代价与风险最大：① 它从未编译过（接线成本未知）② 每次动作加验证 = **延迟与 token 成本上升** ③ 排期 §2 已有前车之鉴 —— mu 的 admission 实测「2412 块 drop 0 个、吃掉 54% 判断输入」，本仓若照搬同一模式，可能重犯「高成本零收益」 |
| **C. 只迁审计，不迁验证** | 只把 `Auditor` / `AuditLevel` / `AuditRecord` 接到现有 loop | 中庸：审计成本低（只记录不阻断），又能补上「可观测」缺口。⚠️ 需先确认 `nt_core` 是否已有等价审计面 |

### 我的推荐：**A（先归档，不接线）**，理由三条

1. **它是唯一有实证反面教材的相关案例**：排期 §2 记录 mu 对**同类决策点**（chunk 准入）
   实测「drop 0 个 / 54% token」。在没有本仓自己的数据前，**接线等于复制一个已知高成本模式**。
2. **接线成本未知**：它从未进入编译树，连「能否编译」都未验证（O-3 的 `#[path]` 事件已证明
   长期未编译的代码随时可能已腐化）。
3. **31 个测试是可复活资产**：归档而非删除，保住「这一层曾被设计并验证过」的证据；
   真需要时能取回，且取回成本远低于「重新设计」。

⛔ **但 A 不是「放弃」**：需在基线里把它的状态从「有意不挂载」改为
「已裁决：暂不接线，理由 =缺本仓数据 + 从未编译验证」，并写明**复活条件**
（M-14「限制四段式」的 `Retirement Trigger` 思想）：
什么条件满足时重新评估接线。
