# 第一性原理流式化分析

## 核心公理

Agent 对话上下文 = 易失内存。任何有价值的数据必须在产生的**时刻**流式写入持久层。

## 全量数据流审计

### 已流式化 ✅

| 数据流 | 机制 | 时机 |
|--------|------|------|
| websearch 结果 | `absorb_web_result()` | 每次搜索后 |
| webfetch 内容 | `absorb_web_result()` | 每次抓取后 |

### 仍为易失 ❌ — 按影响排序

```
Tier 1 (高影响, 简单实现):
┌────────────────────────────────────────────────────────────────────┐
│ 1. Build/Test 结果      cargo check/test 的输出只在对话中           │
│ 2. 模式/缺陷发现        P## 模式只在对话中被命名和讨论              │
│ 3. Session 里程碑       阶段切换、关键发现只在对话中                 │
│ 4. 架构决策/ADR         为什么选A不选B只在对话中                     │
└────────────────────────────────────────────────────────────────────┘

Tier 2 (中影响):
┌────────────────────────────────────────────────────────────────────┐
│ 5. 代码变更记录         编辑了什么、为什么只在对话中                │
│ 6. 用户指令/约束        用户说"不要用X"只在当前session有效          │
│ 7. 错误恢复模式         怎么修好一个bug的过程丢失                  │
└────────────────────────────────────────────────────────────────────┘

Tier 3 (低影响):
┌────────────────────────────────────────────────────────────────────┐
│ 8. Git 操作意图         为什么做这次commit只在commit message        │
│ 9. 元认知发现           "我发现了一个模式"类自省丢失                │
│ 10. 工具耗时/频率        哪个工具最慢, 无法统计                     │
└────────────────────────────────────────────────────────────────────┘
```

## 统一解决模式

所有流式问题共享同一个模式:

```
Agent 产生数据 → absorb_xxx() → KB INSERT/UPDATE → 其他session可检索
                        ↑
                  3-5行代码
```

每个 `absorb_*` 函数就是一个 KB 写的薄封装。

## 实现 Priority

| # | 数据流 | 函数 | 代码量 | 影响 |
|---|--------|------|--------|------|
| 1 | Build/Test 结果 | `absorb_build_result()` | ~20行 | 跨 session 构建健康追踪 |
| 2 | 模式/缺陷发现 | `absorb_discovery()` | ~15行 | 模式立即被其他session检索 |
| 3 | Session 里程碑 | `absorb_checkpoint()` | ~10行 | 崩溃恢复 + 会话连续性 |
