# NT-GAME: Hexagram Crucible — 自我映射的自进化游戏

**Date**: 2026-09-02
**Status**: DRAFT
**核心理念**: 游戏世界就是 NeoTrix 意识核心的镜像 — 每个游戏机制直接映射一个内部模块，游戏难度随进化版本自动调整

---

## 1. 设计哲学

### 为什么不能用通用游戏？

通用游戏（2048、扫雷）的问题：
- 与 NeoTrix 的认知架构脱节
- 训练出的技能难以迁移到代码/推理任务
- 无法反映系统当前的进化状态
- 游戏机制与意识核心没有结构性同构

### NT-GAME 的原则

> **游戏世界 = 意识核心的外化**
> **游戏操作 = 认知操作的游戏化表达**
> **游戏进化 = 意识进化的同步映射**

每个游戏机制 **必须** 满足以下条件之一：
1. 直接映射 NeoTrix 的一个模块（结构同构）
2. 训练一个 NeoTrix 缺失的认知能力（能力补全）
3. 强化现有模块之间的连接（跨域整合）

## 3. 核心游戏机制：每个机制映射一个内部模块

### 3.1 卦象导航 (E8 Hexagram Navigation)

**映射模块**: `nt_core_e8` — 64 卦象推理引擎

**游戏机制**:
```
┌─────────────────────────────────────────┐
│  游戏世界由 64 个「卦域」组成              │
│  每个卦域 = 一个六线卦象 = 一种认知模式     │
│                                         │
│  玩家当前位置 = 当前推理模式              │
│  移动 = 推理模式转换                      │
│  转换规则 = E8 根系统的 240 个根向量       │
│                                         │
│  六线含义 (游戏化):                       │
│  第 6 线 (顶): 信息密度 — 当前信息量       │
│  第 5 线: 威胁等级 — 失败风险              │
│  第 4 线: 机会数量 — 可用资源              │
│  第 3 线: 不确定性 — 隐藏信息量            │
│  第 2 线: 动量 — 当前趋势方向             │
│  第 1 线 (底): 复杂度 — 问题难度           │
│                                         │
│  互补卦象 = 对立视角                      │
│  例：乾(111111) ↔ 坤(000000)             │
│  强制切换 = 强迫自己从对立面思考            │
└─────────────────────────────────────────┘
```

**训练的认知能力**: 推理模式切换、多角度思考、状态空间搜索

**自适应规则**: 进化版本越高，可探索的卦域越多（C0=8 卦域，C6=64 卦域全开）

### 3.3 VSA 符号操作台 (VSA Operation Table)

**映射模块**: `nt_core_hcube` — 向量符号架构

**游戏机制**:
```
┌─────────────────────────────────────────┐
│  VSA 操作台:                              │
│                                         │
│  玩家持有「知识向量」(4096维)              │
│  三种操作 = 三种游戏动作:                  │
│                                         │
│  🔗 绑定 (Bind):                         │
│  将两个概念绑定为一个新概念                │
│  例: bind("火", "山") → "火山"            │
│  游戏效果: 创建复合概念，可用于后续解谜      │
│                                         │
│  📦 捆绑 (Bundle):                       │
│  将多个概念叠加为一个模糊概念              │
│  例: bundle(["火","热","红"]) → "火的意象"  │
│  游戏效果: 概念融合，获得模糊但全面的理解    │
│                                         │
│  🔄 置换 (Permute):                      │
│  概念的循环移位 = 视角转换                 │
│  例: permute("火", +1) → "火的对立面"      │
│  游戏效果: 创造性视角，发现隐藏关联         │
│                                         │
│  🎯 相似度 (Similarity):                  │
│  测量两个概念的相似程度                     │
│  游戏效果: 判断概念是否匹配谜题要求         │
│                                         │
│  谜题设计:                                │
│  给定目标向量 T，用 bind/bundle/permute    │
│  从初始向量集合构造出 T                     │
│  最少操作步数 = 最高分                     │
└─────────────────────────────────────────┘
```

**训练的认知能力**: 符号推理、概念组合、类比思维

```rust
/// 任何游戏实现此 trait 即可接入 NT-GAME 系统
pub trait NtGame: Send + Sync {
    /// 游戏名称
    fn name(&self) -> &str;
    
    /// 适合训练的认知维度
    fn target_cognitive_skills(&self) -> Vec<CognitiveSkill>;

    fn observe(&self, state: &GameState) -> Observation;
    
    /// 获取合法操作
    fn legal_actions(&self, state: &GameState) -> Vec<GameAction>;
    
    /// 执行操作
    fn step(&mut self, state: &mut GameState, action: &GameAction) -> StepResult;
    
    /// 是否结束
    fn is_terminal(&self, state: &GameState) -> bool;
    
    /// 计算奖励 (多维度)
    fn reward(&self, state: &GameState, action: &GameAction) -> RewardVector;
    
    /// 获取 E8 卦象编码
    fn to_hexagram(&self, state: &GameState) -> Hexagram;
    
    /// 获取 VSA 编码 (用于记忆存储)
    fn to_vsa(&self, state: &GameState, vsa: &VSAEngine) -> Vec<f64>;
```

### 6.3 进化同步接口

```rust
/// 进化同步器 — 监控 NeoTrix 进化状态，自动更新游戏
pub struct EvolutionSync {
    last_constellation: u8,
    config: GameConfig,
}

impl EvolutionSync {
    /// 检查并同步进化状态
    pub fn sync(&mut self, neotrix: &ConsciousnessTree) -> Option<EvolutionEvent> {
        let current = neotrix.overall_constellation();
        if current != self.last_constellation {
            let event = self.unlock_new_mechanics(current);
            self.last_constellation = current;
            Some(event)
        } else {
            None
        }
    }
    
    /// 根据 constellation 等级解锁新机制
    fn unlock_new_mechanics(&mut self, constellation: u8) -> EvolutionEvent {
        match constellation {
            0 => EvolutionEvent::BasicMechanicsUnlocked,
            1 => EvolutionEvent::EmbodimentUnlocked,
            2 => EvolutionEvent::EmotionUnlocked,
            3 => EvolutionEvent::CognitionUnlocked,
            4 => EvolutionEvent::GardenUnlocked,
            5 => EvolutionEvent::MetaUnlocked,
            6 => EvolutionEvent::FullConsciousnessUnlocked,
            _ => unreachable!(),
        }
    }
}
```
