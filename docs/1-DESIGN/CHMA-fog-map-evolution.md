## 0. 一次范式转换：从"扁平目录"到"迷雾地图"

扁平化架构的本质是**目录思维**：每个节点一个文件、一条 re-export、一个
`pub mod` 声明，所有节点在同质平面里平铺。它解决"哪里找"的问题，但回答不了
三个更深的问题：

1. **这个节点为何存在？**（第一性原理，D-Truth）
2. **它依赖什么、被什么依赖？**（拓扑关系，非文件位置）
3. **它离"更好"有多远？**（成熟度梯度，非布尔存在）

迷雾地图把这三个维度统一：**能力是对世界的部分可观测认知，图是认知的地平线。**

- 一开始你什么都没有 → **全迷**（全仓 = 未探索）
- 你解决一个任务 → 过程中的流程、平台、调用关系被记录 → **这块雾散了**
- 你迭代认知 → 处理能力的路径越清晰、越迅速、越接近最优 → **地图既视感增强**

NeoTrix 的 `ConsciousnessTree` 已经在做这件事的点子系统——NodeTier / RuneSocket /
Constellation / WeaponSet 就是"节点如何进化"的雏形。本设计把这些点状机制收拢为
**统一高维拓扑 + 一条迷雾退散的主链**，并把 CHMA 四层映射成既有的真实模块，
从而让进化不是"新增抽象"，而是"重新维度化已存在的系统"。

## 1. 设计目标与原则（熔炼用户思想）

### 核心隐喻：能力 = 迷雾地图，进化 = 迷雾退散

> 刚开始你什么都不知道，但是解决了一个任务、实现了一个目标，你在过程中遇到的
> 流程方式、寻找的平台信息，都是你的基础认知地图。你不断迭代认知世界，你的处理
> 事情的能力就越清晰、越迅速、越最优解，你的迷雾地图就越清晰，迷雾就会随着认知
> 不断退散。

映射到代码：**每次成功接线一个节点到生产路径，就是一次迷雾退散。**

### CHMA 四层统一（意识-混合元架构）

| 意识层次 | 认知动作 | 生产模块映射（真实） |
|----------|----------|----------------------|
| **L1 现象场** | 观察现状 · 基线 | `nt_memory_kb` 基线 + `nt_core_graph` 拓扑 |
| **L2 选择意识** | 聚焦 · 注意力调控 | `AttentionManager` + `WeaponSet` + `ConsciousnessTree` |
| **L3 意识选择** | 决策 · 行动 | `nt_core_gate::GateDecision` + `nt_core_scheduler` |
| **L4 元认知** | 自省 · 重构 · 优化拓扑本身 | `nt_core_self_review` + `nt_core_observer` + `nt_core_meta` |

**关键论断**：CHMA 四层不是"要新增的四层"，而是 NeoTrix 已存在的四个子系统
被赋予的**观察者视角层级**。扁平→高维不是加节点，而是给每个节点标注其在
四层认知中的生态位 + 迷雾浓度。

### 最优标准（用户七条）

1. **完整** — Zachman 全矩阵检查（How/What/Where/Who/When/Why × 维度）
2. **可执行** — TOGAF ADM 过程驱动
3. **心理灵活** — 意识第四层（元认知）贯穿
4. **可观测** — 灰度：C0-C6 成熟度 + 迷雾浓度
5. **可演化** — 元层允许吸收新架构
6. **分层解耦 + 递归互动** — 低层支撑高层，高层调控低层
7. **轻量务实** — 先 Hello World 再图，拒绝官僚

## 2. 高维拓扑：三个正交轴

扁平目录只有一条轴（可以叫"层"或"目录"）。迷雾地图给它补上两个正交维度，
形成**三维能力空间**：

```
                成熟度轴 (Constellation C0-C6)
                     ▲
                     │ C5 自愈/自适应
                     │ C4 主流水线
                     │ C3 benchmark
                     │ C2 集成测试
                     │ C1 单元测试
                     │ C0 编译
                     └───────────────► 拓扑轴 (依赖/调用关系)
                     /
                    /
           迷雾浓度 (未验证的死代码 / stub / dormant)
```

### 轴 1 — 拓扑轴（Space）：节点关系图谱
- 来源：`nt_core_graph`（数组依赖图）+ `nt_core_knowledge`（领域关系）
- 每个节点标注：**消费者**（谁依赖我）/**供应商**（我依赖谁）
- 迷雾判定：一个节点无消费者 → 它是"未探索边界"（孤儿/死代码）→ 迷雾浓
- 本审计已完成的第一刀就是**迷雾清退**：归档 39+ 孤儿节点 ≈ 雾退 27K 行

### 轴 2 — 成熟度轴（Maturity）：凋谢→开花
- 来源：`Constellation::derive()`（C0-C6，源于真实 SelfTest/集成状态）
- 这是**进化链的主干**：C0 迷雾 → C5 清晰
- 已有 `NodeTier`（Small/Notable/Keystone）给成熟度定"期望值"：
  Keystone 节点停在 C2 是异常（雾浓），Small 节点到 C4 是过度（浪费雾）

### 轴 3 — 迷雾浓度轴（Fog）：可观测性的反面
- 新量纲：`fog = f(dead_code, stub, dormant, missing_test, orphan)`
- 发布机制：`NodeSnapshot`（已存在）加 `fog_level` 字段
- 目标函数：**每次进化操作让生命线的加权雾和下降**
- 溯源："昨天雾在这里 → 今天是哪个提交驱散的"（雾退散日志）

## 3. 进化链式拓扑（链 = 雾退散的生命线）

单一进化目标让混沌变成链。这里给出**三条生命线**（chain），每条是从 L1 到 L4
的递归闭环。用户思想里的"能力网进化"落成：**任何进化都是把迷雾沿链推向清晰**。

```
┌────────────────────────────────────────────────────────┐
│  [L1 现象场]                              [L4 元认知]   │
│  ┌──────────────────┐        ┌──────────────────────┐  │
│  │ nt_memory_kb 基线 │──观测─►│ nt_core_self_review  │  │
│  │ nt_core_graph 拓扑│        │ nt_core_observer      │  │
│  └────────▲─────────┘        └──────────┬───────────┘  │
│           │                             │ 重构/优化     │
│  ┌────────┴─────────┐        ┌──────────▼───────────┐  │
│  │ L2 选择意识       │──决策─►│ L3 意识选择           │  │
│  │ AttentionManager  │        │ GateDecision         │  │
│  │ WeaponSet         │        │ Scheduler            │  │
│  │ ConsciousnessTree │        │ (C0-C6 晋级裁决)     │  │
│  └──────────────────┘        └──────────────────────┘  │
│        ▲ 向上支撑                        │ 向下调控      │
└────────┴────────────────────────────────┴──────────────┘
```

每一条生命线遵循统一协议（Climate — 融合 CHMA + Hayden）：

```
1. 观察(L1)   ：采集节点真实状态（编译/测试/集成/引用数）→ 更新迷雾浓度
2. 聚焦(L2)   ：WeaponSet 路由 + AttentionManager 挑选本轮要驱散的雾区域
3. 决策(L3)   ：GateDecision 裁决该进化是否值得（成本×收益×风险）
4. 行动(L3)   ：接线/归档/重构（本审计已示范：归档孤儿）
5. 自省(L4)   ：SelfReview 检验是否引入新雾（平行适配器/Dark Forest）
6. 回流(L4→L1)：更新基线与拓扑 → 雾退散日志落地 → 下一轮
```

### 三条生命线（按价值和当前缺口排序）

**生命线 A — 接线度（"让它生产化"）**
- 目标：把 C0-C2 节点推到 C3+（接入真实流水线）
- 迷雾源：死代码/dormant/stub（本轮已清除一批，待续）
- 关键缺点修复：吸收器 4 套 / 代理栈 7 套 / 蒸馏器 4 套等警告项
- 判据：`weighted_fog_sum` 单调下降

**生命线 B — 成熟度（"让它开花"）**
- 目标：Constellation 从 bool 布尔 → 真实遥测驱动
- 重点：Keystone 节点（跨 2+ 域）不得停在 C2
- 判据：C4+ 节点占比上升；Keystone 无一在 C2 迷雾滞留

**生命线 C — 认知覆盖（"让边界知道"）**
- 目标：元认知能回答"系统最强/最弱/最空白的域"
- 迷雾源：消费链断裂（world_map←spatial 等 3 组已记录）
- 判据：元认知健康分（nt_core_self_review 输出）随雾退散而升

## 4. 观察者视角贯穿（L4 元认知如何落地）

用户强调"组织支持扁平化……通过 L4 元认知实现快速决策与自组织"。映射：

- **扁平**：任何节点可通过 `NodeSnapshot` 被同等观测（不因层级被豁免）
- **自组织**：`AttentionManager` 动态路由（现已有 `from_task_type`）决定本轮
  聚焦哪条生命线，而非刚性层级命令
- **快速决策**：GateDecision 轻量裁决（现已有 `check_path`），拒绝官僚审批
- **元认知健康**：`nt_core_self_review` 自带 `check_layer_violations`（已有）——
  它在防"新雾"：防止 `core/` 回流 `neotrix::`（本轮 L1 迁移否决正是它的功劳）

**元认知的关键反例（本轮实证）**：分析师曾建议"补全 L1 门面 re-export"（方案 Y），
但 `check_layer_violations` 会把它识别为 layer violation。**元认知在这里拒绝了**
一个看似合理、实则制造新雾的方案——这就是自组织优于直觉的证据。

## 7. 后果

### 正面
- 把"进化"从口号变成可测度、可观测、可溯源的操作：**雾退散**
- CHMA 四层不新增抽象，而是给 10 层阵眼 + 星系节点一个统一的生态位语言
- 三条生命线提供清晰的优先级（接线 > 开花 > 知边界）
- 元认知自组织替代刚性层级，对齐"扁平化 + L4"

### 负面/风险
- 迷雾测度若依赖假数据，会重蹈"假遥测"（Constellation 若硬编码就是雾里雾）
- 三条生命线若全部并行推进会失焦（用户也说"优先决策价值"）
- 高维可视化可能过度工程（拒绝为图而图）

### 缓解
- 迷雾浓度只从真实数据 derive（引用计数/测试/集成），无硬编码
- 分阶段：先 Phase 0 量纲，验证"雾真的能退"再铺开
- Phase 3 可视化紧随数据产生，不先建图再填数
- 每链独立判据，避免摊大饼
